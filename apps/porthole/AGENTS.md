# Porthole: agent brief

## What this is

Porthole is the device firmware: a shared runtime (`os/`), the board layer (`firmware/`), the shell (`shell/`: "Who's playing?", up to four profiles, the launcher, the rest timer) and the games compiled into one image (`games/`). Its first game is Pets Club. The second, Biscuit, was rewritten onto this same runtime (it previously shipped as a standalone LVGL firmware and was removed in PR #24), with full content parity. Design: `docs/superpowers/specs/2026-09-24-launcher-profiles-design.md` (shell/profiles) and `docs/superpowers/specs/2026-09-25-biscuit-on-porthole-design.md` (Biscuit) at the repo root.

Pets Club is a touch-only, Tamagotchi-style dog companion for the Waveshare ESP32-S3-Touch-LCD-2.1, a round 480x480 capacitive-touch panel with no physical buttons. It is built for kids aged 5-10 who like reading and dogs: the pet grows over real calendar days, learns eight tricks over three lessons each, and is read twenty-plus original stories from a library that unlocks with daily gifts. Each profile on the device has its own pet, room and reading level (from the profile's age); Paw Street shows every profile's house. Everything renders into a 160x160 indexed-color framebuffer (32-color palette) that gets upscaled 3x to the physical panel. The pet never dies, never runs away, and never resets: stats decay toward floors, not through them. The one exception, decided by the parent on 2026-11-08, is the kid's own choice: an old dog (day 30 or later) can move to the farm, which keeps the kid's progress and keeps the dog on the room's memory wall, and the kid then picks the next pup at the shelter (until then, Bring back undoes the move). Its own brief, with the Save layout and reading-level tables: `games/pets-club/AGENTS.md`.

Biscuit is a warm, doglike reading and discovery companion on the same panel, drawn full-color at native 480x480 instead of Pets Club's indexed look. Its product contract, module map and content limits: `games/biscuit/AGENTS.md`.

It lives at `apps/porthole/` in the porthole monorepo (apps for this board sharing build/test/deploy infrastructure). Every path below is relative to `apps/porthole/`, and every command runs from there (or as `make -C apps/porthole <target>` from the repo root). The shared PlatformIO board base is `../../platform/waveshare-round.ini`. Read a game's own `AGENTS.md` before touching it; this file covers what every game shares.

## Architecture map

`os/`, `shell/` and each game under `games/<game>/` are the platform-agnostic core. They compile unchanged into both the firmware and the host simulator (`-DHOST_BUILD` only changes what `main()` exists, not the game logic). The include path is `-Ios -Ishell -I.`: `os/` and `shell/` headers by bare name, a game's own headers by bare name (same directory), and a game's headers from anywhere else by path (`games/pets-club/game.h`). `os/` never includes anything from `shell/`, `games/` or `firmware/`; games include only `os/`; the shell knows games only through `os/app.h` (one exception: `shell/migrate.cpp` reads a game's old save layout once, for a one-time migration -- Pets Club's old houses today, Biscuit's old NVS blob once its migration lands).

In `shell/`:

- `profiles.h` / `profiles.cpp`: the profile record (`porthole/p<id>`, append-only with magic/version/size/crc, `MAX_PROFILES = 4`, currently version 4 / 96 bytes with the kid's star balance `stars` and then the skills book `book` (`os/skills.h`, 40 bytes, handed to a game as `AppEnter::book`) last; the star balance (`os/stars.h`, handed to a game as `AppEnter::stars` and saved as soon as a game changes it, in the same tick as and right after the game's own save, which holds what the stars bought); `REC_V1_SIZE = 44`, `REC_V2_SIZE = 52` and `REC_V3_SIZE = 56` still load, with no stars or no book), create/delete (both erase `s<id>` in every game's namespace and an older firmware's favorites `porthole/f<id>`), the per-session rest budget (parent-configured minutes, default `SESSION_SEC`; `REST_SEC` break, even with one player), the daily play cap (parent-configured minutes, default `DAILY_SEC` = 30 min per profile per local day, across every game, kept as `(playDay, dayPlaySec)` rather than a deadline so a new day or a clock set back just resets it -- `playedToday()`/`restLeft()` read it, `shell::play()` updates it), `IDLE_MS` (a minute without activity counts toward neither budget; also the firmware's first backlight-dimming step. Activity is a touch or a move of the board -- gravity more than `ActivityTracker::MOVE_MG` = 200 mg from where it was at the last activity -- so hands-off tilt play counts and a board lying still does not; `ActivityTracker` in `os/input.h` is the one rule, the shell and the firmware's dimming each run one, and a move wakes a dark screen without becoming a touch. A product decision, not an oversight: any move over 200 mg counts, a car ride, a bag or a bumped nightstand included. That is the conservative side for the daily cap (more time counts, never less), it keeps the screen lit while the board is being carried, and at bedtime (`asleep()`) a bump lights the screen at 40% for 20 s and nothing more), `liftCaps` (called from `Shell::clockRestored()` when the firmware had to guess the clock after losing the RTC: "today" cannot be trusted -- every cap lifts, like a clock set back), and the `Store` interface both platforms implement. `host/test_shell.cpp` exercises it directly.
- `migrate.cpp`: first boot on a Pets Club device: house `crago/s<n>` becomes profile `n` (same slot, no save moves; the older `save` key is copied to `s0` only when no house exists). Runs until the marker `porthole/m` is written, so power loss mid-migration just re-runs it. `migrateBiscuit` does the same once for Biscuit's pre-Porthole save (`zoegotchi/pet3|pet2|pet1` or `biscuit/pet1` -> `biscuit/s<id>`, marker `porthole/mb`); `loadAll` runs it after the Pets Club migration.
- `pinlock.h`: guessing a code. Header-only, one `PinLock` per kid's code (by profile id) and one for the admin code (`ADMIN_LOCK`), in the versioned 44-byte `"sys"/"pinlock"` blob so unplugging does not skip a wait. Three wrong tries in a row are free; each one more makes the next try wait 5, 10, 20, 40, then 60 s (`PIN_MAX_WAIT`, a user decision of 2026-11-01: enough to make guessing hopeless, never a long lockout). Each lock records the stored code its strikes were counted against (`PinLock::code`), so they stop counting the moment that code changes (a grown-up sets, removes or clears it, or a new profile takes the slot) with no clearing hooks; they also clear on the right code and after an hour with no wrong try (`PIN_FORGET_SEC`). `loadPinLocks` validates the blob; a `savePinLocks` write that does not land only lets a reboot skip the wait. A clock set back restarts the wait from now, never longer than the cap. While a wait runs the kids' pad (`pin`) hides its keys behind an hourglass whose sand runs down, the seconds and a bar that empties ("Wait a little"); a tap wiggles the hourglass (silently), and the keys come back only once the wait is over and no finger has touched the glass for `PIN_CALM_MS` (1 s), so a kid tapping through the end of a wait never types junk digits that start a longer one (a playtest finding of 2026-11-01). `pinWait()` settles the lock in RAM each frame, so a clock set back counts down from then, and `sys_pin` says "Too many tries" / "Try again in N s"; back always works and leaving does not reset it. Choosing a code (`pin_set`, `sys_pin_set`) is never throttled. `debug` prints `[codes pin_wait= admin_wait=]`. Tests: `pinWaits`, `kidCodeLockout`, `adminCodeLockout` in `host/test_shell.cpp`; playtest `tests/playtests/a7_code_waits.txt`.
- `shell.h` / `shell.cpp`: the `Shell` class: picker, new profile (name, face, age, code), code pad, delete, launcher (the brightness lives here: see below; sound is one device-wide switch, `"sys"/"sound"`, on Admin page 2 since a user decision of 2026-10-31: kids never used a mute button for a buzzer the games barely use), rest screen ("Back in N min" for a turn-taking rest, or "Back tomorrow" once `playedToday()`, with no countdown), and hosting the open game (`App`): it writes the game's save at most every 5 s (an `App::saveUrgent()` checkpoint after at least 1 s) and on leaving, never rewrites bytes identical to what it last wrote or loaded, and retries a failed write from its own copy at that cadence, doubling the wait after each failure in a row up to about 5 minutes (a full or worn-out NVS; leaving the game still tries once) and telling the grown-up with one line on Info ("Saves failing: storage full?", gone once a save lands; a kid sees nothing), and gates the buzzer with the Admin sound switch. `dbg bedtime` (see the `tour` skill) uses up today's budget for testing; `debugPrint()`'s `today=` key reports seconds played today.
- Brightness (`shell::Light`, one per device, one byte in NVS `"sys"/"lite"`, the shell's second `"sys"` key; missing or out of range is Auto): the launcher's sun button (`launcher::LIGHT`, right of the header, which is narrowed to fit it and still holds the widest 8-letter name) opens the `light` screen: three suns, big to small, for Bright / Medium / Soft, and Auto (a sun and a moon) under them; a tap picks, saves and returns to the launcher (two taps in all; the home button leaves it unchanged). The sun button shows the level picked. Auto is the old behavior: `clockTint`, a full backlight. Bright / Medium / Soft are always daylight -- `Shell::tint()` is `TINT_DAY` on every shell screen (the rest screen too), and a game gets `AppEnter::daylight` and returns `TINT_DAY` with day scenes (Biscuit's rooms, Pets Club's window and Paw Street); a game's own night (a pet asleep) still holds -- at `shell::LIGHT_BACKLIGHT` 100 / 65 / 40 %. `Shell::backlight()` is that active level; `shell::backlightFor(asleep, idleMs, active)` (`shell.h`, tested in `host/test_shell.cpp`) is the whole rule `dimWhenIdle()` in `firmware/main.cpp` applies: the active level, 30 % after `IDLE_MS`, dark after 5 min, and a game `asleep()` 40 % then dark after 20 s, the same at every level (the updater needs the dark). The `Light` values are persisted: append only, before `LIGHT_COUNT`. Sim: snapshots show the active backlight (`dimmed()` in `host/sim.cpp`), `dbg light` or the window's `b` key picks the next level, `debug` prints `bright=` and `backlight=`, a `reboot` keeps it. Playtest: `tests/playtests/24_brightness.txt`.
- The launcher (`launcher`, `shell.cpp`): every game switched on, six a page in the grid of `launcher.h`, with page arrows; a game opened there comes back to its page, and a new pick from the picker starts on page 0. No favorites, stars or per-kid lists: the parent tried a kid-picked Home of favorites with a Library of every game (PR #145) and had it removed on 2026-11-16 ("I don't want the customization or ability to choose which games are favorites"). Older firmware wrote those favorites to `porthole/f<profile id>` (24 B); nothing reads it now, it stays on an updated device (so a USB rollback still finds it) and a profile's create and delete erase it. Every game has a stable 1-byte id, 1..32, in `APP_IDS` next to `APPS[]` in `games/apps.h` (never changed or reused, even after its game leaves the image; a `static_assert` holds them unique), which the grown-ups' Info -> Games mask uses. `enabledGames` in `profiles.h` is the one list the launcher, `open` and Info -> Games read. Tests: `launcherPaging`, `gamesOffBlob`, `oldFavoritesIgnored`, `adminGames` in `host/test_shell.cpp`; playtest `a2_launcher_pages`. `debug` prints `[home home_tiles= home_first= home_page= home_pages= games_off=]` for the launcher's current page.
- `launcher.h`: the launcher's geometry as pure functions, for up to `MAX_APPS` (12) games: six to a page in two rows of three 40x30 picture tiles (a short last row centered), so twelve games are two pages, behind a pair of arrows under the grid. Each tile shows its game's `App::icon()`, a 38x28 picture in the shell palette that every game generates from `games/<game>/art/launcher.png` with `tools/launcher_icons.py` (Codex art; principles and prompts in `docs/launcher/README.md`). Names are not drawn under tiles: a finger on a tile shows its game's name in a yellow caption over the header row (`CAPTION`). The sim asserts at boot that every game's name fits the caption and its picture fits a tile, so a long name or a big icon fails `make playtest`. The light screen's three suns keep their own 44 px row (`sun(i)`). `host/test_shell.cpp` holds every layout to the round glass and pages through a `Shell` with stub games.
- `system.h`: `shell::System`, the device side of wireless updates as the shell sees it (`info()`, `status()`, `checkNow()`, `restart()`, the Stable/Beta channel), the `UpdState` states (`UP_COUNT` last, for tables), and `parseVersion`/`newer` (only strictly newer real releases; "dev" never). Its wifi half: `startScan`/`scanResult` and `startTest`/`testResult` (-1 while running), `saveWifi` (a resting "No wifi" or "Check failed" goes back to idle: it was about the old network), and `addNetwork` (the scan list). The radio does one job at a time: a scan or a test is refused while the update check runs, and Check now or the daily check does nothing while a scan or a test runs; the firmware runs each as a task on core 0 and turns wifi off after it. Firmware implements it in `firmware/net.cpp`, the sim with a canned `SimSystem`. Design: `docs/superpowers/specs/2026-10-17-wireless-updates-design.md`.
- `sysmenu.cpp`: the "something new" card (`sys_new`, once on the first boot of a new version: `shell::newRun` compares the running version with `"sys"/ran`, a shell-owned `"sys"` key (alongside `lite`, `admin`, `limits` and `games`); "dev" never shows it) and the grown-ups' system menu, reached by holding the picker's title 5 s (only with a `System`): Info (`sys_info`: version, slot, reset reason, heap, SD, wifi, and a line when the last game save did not land; buttons Wifi, Games, Updates and, on a build with a lookup (`System::hasHome`), "Radar home", so it is not taken for the kids' Home), Updates (`sys_updates`: channel switch, locked while checking, downloading or ready; Check now, hidden while a wifi scan or test holds the radio; Restart now, which needs no radio) and Wifi: `sys_wifi` (a scan's networks, strongest first, one per name, no hidden ones, 4 a page, signal bars and a lock; Rescan), `sys_pass` (a secured network's password on a full QWERTY keyboard, a user decision of 2026-10-18: rows of 10, 9 and shift + 7 + backspace, then page, space and OK; three pages of 26 -- letters with a shift lock, digits and symbols, more symbols; keys of 12x18 px (4 x 6 mm, `KEYBOARDS` in `tools/playtest.py` lets them under the 18 px floor), every tap going to the nearest key and the key under the finger shown big above it; any printable ASCII up to 64; shown as `*` but the last letter, never whole), `sys_join` (a test join with the typed password, which is saved only if it joins; Try again keeps the typing, Save anyway saves it untested; an open network skips the keyboard; while the radio is busy, an update included, it waits ("Waiting for the update") and then tests; a failed save says "Could not save" with Try again), and Home, where Radar centers, one per device: `sys_home` (the place set, or "nothing yet"; Set address), `sys_addr` (the address on the same QWERTY keyboard, shown in full), `sys_find` (the lookup, a radio job like a scan that waits for the radio; "Is this home?" with the place found, saved only on Yes; No and "Could not find that address" go back to the typing, kept; a failed save says so). The address is sent once, to the geocoder, when OK is tapped; only the coordinates and the place's town, region and country are kept, never the street address (`System::home`/`saveHome`; the firmware asks Nominatim for `addressdetails` and keeps those three). The menu is for grown-ups, a user decision of 2026-10-18: it renders at native 480x480 with anti-aliased Atkinson Hyperlegible Regular (`shell/adult_fonts.h`, bundled SIL OFL font under `shell/fonts/`), with 18 logical px (6 mm) targets instead of the kids' 24x22 buttons. Body text is 24 physical px, headings 28 px and keypad digits/key previews 32 px; labels use the same font metrics for measuring, fitting and drawing; `sys_new` is the kids' and keeps their rules. Shell palette only, no sound. `shell::addNetwork` (`system.h`, the scan list) and `shell::TextEntry`/`textKey` (`shell.h`, the keyboard's editing) have unit tests in `host/test_shell.cpp`. Sim script: `sys version V | newest V | nowifi | current | download PCT | ready | failed`, for wifi setup `sys scan | scanempty` (the running scan ends with canned networks, or none) and `sys joinok | joinfail` (the running test join ends so), `sys savefail` (the next save fails), for Home `sys found | notfound` (the running lookup ends so), `sys homefail` (the next save fails), `sys nohome`, and `reboot`; `debug` prints `sys_*` keys (the sim's `sys_pass` is the saved password, host only). Playtests: `tests/playtests/19_system_menu.txt`, `tests/playtests/24_wifi_setup.txt`, `tests/playtests/25_home.txt`.
- Admin controls (`sysmenu.cpp`): the five-second picker-title hold asks for an optional device-wide four-digit code before Info (`sys_pin`); every return to the picker ends access, and a reboot asks again. With a code set, the picker's New asks for it too (`sys_pin`, then the name keyboard; back returns to the picker), so a fresh profile cannot dodge the limits. Deleting a profile (a picker row held 3 s, `DELETE_HOLD_MS` in `shell.cpp`; any shorter press opens that profile, through its code if it has one, because a 6-year-old holds their own name 1-3 s to play (kid playtest 8, 2026-11-09), and a plum bar fills under the name from 1 s on) always takes a code, a parent decision of 2026-11-09 (two long presses by a small kid deleted a profile): a profile with a PIN asks it on the kids' pad (`pin`), drawn navy with "Delete <name>?" for its prompt (and a wait's hourglass outlined in white) so it never looks like signing in (a kid typed their code there by habit), whose "Admin" key (in the skip slot, only with an admin code set, shown during the kid's wait too) goes to `sys_pin` for the grown-up's code instead (back from there returns to the kid's pad); one with no PIN asks the admin code (`sys_pin`); with neither, nobody can delete it, and the hold shows the kid-safe `no_delete` card (the profile's face beside the picker's dark gray lock, "To delete <name>, ask a grown-up to set a code in Admin.", OK and the home button back to the picker). Either code leads to the same "No, keep!" / "Hold to delete" screen, and each counts its wrong tries in its own `PinLock`, so one in a wait never blocks the other (`deleteNeedsACode` in `host/test_shell.cpp`; playtests `13_profiles_delete`, `29_admin_profiles`). Info -> Admin (`sys_admin`) offers Set / Change code (masked, confirmed twice: `sys_pin_set` / `sys_pin_again`) and Remove code (`sys_remove`, confirmation). The separate uint16_t `"sys"/"admin"` stores `pinCode`, 0, missing or any other size = off; a write the store refuses changes nothing ("Could not save code"). Player PINs (`sys_players`) maps each row through `nth()` to its stable id and confirms (`sys_player_pin`) before removing only that player's PIN; failed save readback restores the prior record. Admin has Screen time (`sys_time`), which consolidates session and daily allowances (defaults 15/30 minutes, range 1..1440, tap +/-1 or hold +/-10), the optional play window (`sys_window`, enabled by default 14:00 inclusive–19:30 exclusive, supports overnight), Reset usage (`sys_reset`, confirmed) and Allow 30 min (`sys_allow`, confirmed, can end early). The single-limit editor is `sys_limits`. Editors save explicitly; Back discards. Existing `"sys"/"limits"` stays four bytes and existing values survive updates; `"sys"/"window"` is a separate versioned eight-byte blob. Reset clears each used profile's `restUntil`, `playSec` and `dayPlaySec`, preserving settings, lastPlayed, codes and game saves. A RAM-only monotonic allowance bypasses session/daily/window gates while continuing usage; expiry or reboot restores the rules. Merely entering Admin or resetting usage never grants an allowance. All child entry points, launchers and running games enforce the schedule, with game save flush before stopping. Session limits apply even to a single player, followed by the existing ten-minute rest. Info has Games beside Wifi and Updates (`sys_games`, back to Info: a row per game in the image, its picture, name and an on/off switch, three a page with arrows, and the line "Off only hides a game; saves stay."; off hides a game from every kid's launcher, its saves and stars kept; the last game on cannot go off ("Keep one game on"); each switch saves at once and is read back, "Could not save" otherwise; NVS `"sys"/"games"`, `shell::GamesOff`, 12 bytes: version 1, size, a 32-bit off mask by id (bit id - 1), crc; missing or invalid is all on, and a mask that would switch off every game in the image counts as all on; tested in `adminGames`, playtest `b3_admin_games`). Admin page 2 has Clock (`sys_clock`), which shows local time and sync status; named IANA zones (`sys_zone`, searchable via `sys_zone_search`) replace UTC-offset editing. Default America/Los_Angeles, bundled daylight saving rules, saved manual precedence over automatic public-IP guessing, and last-valid fallback when offline. Network time corrects UTC; games use derived local time and play duration uses monotonic milliseconds. Design/state contract: `docs/design/family-screen-time.md`; final black-box evidence: `docs/family-controls/README.md`.
- `shell_sprites.h`: AUTO-GENERATED by `tools/shell_art.py` (avatars, plus, lock, and `SPR_LIGHTS`: the brightness suns in `shell::Light` order). `adult_fonts.h`: AUTO-GENERATED by `tools/fontconv.py --game adult` from the bundled Atkinson Hyperlegible font; the source, license and regeneration instructions live under `shell/fonts/`.

Each game lives at `games/<game>/` and owns its own `AGENTS.md` with its Save layout, content limits and any game-specific detail; this file only covers what every game shares.

Each game also owns its look (root `AGENTS.md`, rule 7). `os/palette.h` is the palette Pets Club and the shell's indexed UI share, not a default for new games: a new game draws on the RGB565 surface with its own colors, fonts and art (or first proposes a per-game palette in `os/`), and never reuses another game's sprites, palette or style.

A game is a directory under `games/`: the Makefile and PlatformIO build every `games/*/*.cpp`, so adding one means the directory, an `App` subclass, its launcher picture (`art/launcher.png`, added to `GAMES` in `tools/launcher_icons.py`), and a `static` instance appended to `APPS[]` in `games/apps.h` with the next unused id appended to `APP_IDS` beside it, the one table the firmware and the sim both run (a `static_assert` holds it to `MAX_APPS`); its `screenName()` values must not repeat another game's or the shell's (`tools/playtest.py` fails on a clash; prefix them). A host test is `apps/porthole/host/test_<name>.cpp` plus one `test_<name>_SRC :=` line in the Makefile -- host tests live in the shared `host/` directory, named per game, not inside the game's own directory.

In `os/`, the shared runtime:

- `app.h`: the contract between the shell and a game (`App`, `Profile`, `SaveSlot`, `AppEnter`, `MAX_PROFILES`, and `enum Surface { SURFACE_INDEXED, SURFACE_RGB565 }` plus `App::surface()`, defaulted to `SURFACE_INDEXED` so Pets Club needs no change; polled every frame, so a game may switch per screen).

Stay indexed even on an RGB565 game: launcher, picker, rest screen and this keyboard are always drawn by the shell.
- `stars.h`: a kid's stars, one balance per profile that any game may award (`stars::award`, capped at `MAX`) or spend (`stars::spend`) through the `uint32_t*` in `AppEnter::stars`; the shell keeps and saves it, `nullptr` makes them no-ops. Learning pays them only through `skills.h`; Pets Club's hats spend them.

A game seeds a skill once (`skills::seed`, from its old level when it had one), asks the level to serve (`skills::target`, about 80% right; a new skill calibrates from easy, jumping 1, 2, 4 levels), reports each answer (`skills::answer`: difficulty, answer count, right, time, a key for repeats), and pays a round at its end (`skills::start` / `skills::finish`): harder for this kid pays more, easy items and repeats pay little, guesses nothing, 100 points a star, the day's first 6 stars count twice, past 40 a day a quarter, a new best level +5, a weekly pace factor. Games that teach nothing pay through `skills::earnForPlay` (10 stars a day across all of them); spending stays `stars::spend`. Times Cards and Pets Club's puzzles and little reads use it; `host/test_skills.cpp` checks the numbers.
- `crc32.h`: the checksum every persisted blob uses.
- `telemetry.h` / `telemetry.cpp`: telemetry, on by default since 2026-11-21 (opt-out, root rule 4): a board with no `"sys"/telem` key starts on; an Off from the menu, the card or serial is kept. `telemetry::emit(name, {P(k, v)...})` from games and the shell is a no-op unless the firmware installed a queue that is on. Admin 2/2 has one switch, "Usage stats": on is the personal level (random board and player ids) to the Porthole PostHog project, key built in (`telemetry::withLevel`); the board's id shows under it. Another backend comes from `/porthole/telemetry.txt` (`posthog|otlp`, an https URL, a token, optional `anonymous`) or serial `Y`; all kept in the one `"sys"/telem` key. Levels: personal (a kid's player id derived from a random salt, the profile slot and name, never stored or sent as a name) and anonymous (only device and game events, a device id that changes monthly). Two bodies: PostHog `/batch/` and OTLP/HTTP JSON logs. `firmware/net.cpp` sends a minute after boot and then every 2 min, during play too, as a radio job. Events: `device_started`, `crashed`, `player_selected`, `game_opened`, `game_closed` (seconds, stars, exit), Times Cards' `times_cards_answer` and `level_finished`. Sim: `sys telemetry`. Tests: `host/test_telemetry.cpp`, `host/test_shell.cpp`, playtest `tests/playtests/2b_telemetry_admin.txt`. Design: `docs/superpowers/specs/2026-11-16-telemetry-design.md`.
- `bits.h`: bit packing for the two saves that would not fit raw (Kingdom, Times Cards): one description of a layout both writes and reads it (`v = b.io(v, n)`); a value too wide for its bits or a short buffer fails the pack.
- `psram.h`: `psram::make<T>()` builds a long-lived object in PSRAM at start-up (the games in `games/apps.h`, the firmware's `Shell`), so it takes no static internal RAM; the host uses the plain heap.
- `save.h`: the envelope every game's save shares (`os::save::Head`: magic, version, size in the first eight bytes; a crc32 of everything before it in the last four) and the one rule the shell applies to a blob it cannot read: `Shell::flushApp` never replaces a stored save that is whole (`sealed`) and this game's from a newer firmware (`newer`: same magic, higher version), which is what an older build flashed over a newer one meets. The game plays on from nothing, nothing of that visit is saved (the kid's stars are put back too), and the save is there again after the next update. A game cannot erase a save either: `*len` 0 writes nothing. Tests: `newerSaveKept` in `host/test_shell.cpp`, `fromNewer` in `host/test_saves.cpp` (every saving game). Games write and check the envelope here instead of each on its own: `os::save::seal(&s, sizeof s, MAGIC, VERSION)` and `os::save::mine(data, n, MAGIC, VERSION, &head)` (whole, this game's, a version this build reads); what size a version must be and whether the fields make sense stay in the game's loader. Marble Kick, Tilt FC, Radar, Rally, Biscuit and Toy Town Life use both, Pets Club the seal (its v1/v2 loader never checked magic or size and still does not); Living Kingdom and Times Cards keep their own code. A game includes it as `"os/save.h"`: plain `"save.h"` is the game's own file wherever it has one.
- `ticks.h`: `millis()` deadlines across the 49.7-day wrap. `os::before(now, until)` is the compare (never `ms < until`), and a deadline kept in a long-lived object is also run through `os::settle` once a frame, so one nobody set again does not read as still ahead 24.8 days later. The shell's toasts and code-pad timers and Pets Club's home deadlines use both. Tests: `uptimeWraps` in `host/test_shell.cpp`, `homeOverTheUptimeWrap` in `host/test_pet.cpp`.
- `day.h`: the one clock policy for daily rules, since the wall clock can jump (set by a grown-up, restored after a flat battery, corrected over wifi). `os::dayOf(now)` is the local day; `os::newDay(today, stored)` is true for any day that differs, an earlier one too, so nothing waits on a date the clock once ran ahead to; `os::elapsed(now, then)` is 0 across a clock set back. The shell's daily cap and rest, Pets Club, Biscuit and Rally's joint-race stars ask it; a new daily rule does too, never a `>` on days. Living Kingdom and Times Cards still keep their own day code. Tests: `clockPutRight` in `host/test_biscuit.cpp`, `giftAfterClockSetBack` in `host/test_pet.cpp`.
- `fastmem.h` / `fastmem.cpp`: one loan of internal RAM for a game's hottest buffer (PSRAM is ~14x slower for random access), only while a wireless update keeps its share, recalled in the dark (`setDark`); the host lends plain heap.
- `gfx.h` / `gfx.cpp`: the indexed-color renderer. A 160x160 indexed-color framebuffer (`gfx::fb`), drawing primitives, the 8x8 font, the round-mask test (`gfx::inCircle`), and the `UiAudit` hit-region log / text-box log that the `ui` sim command and the playtester agent read.
- `gfx565.h` / `gfx565.cpp` and `font.h` / `font.cpp`: the full-resolution surface for games whose `App::surface()` is `SURFACE_RGB565`: 480x480 RGB565 primitives, the 3x indexed-frame expansion, and anti-aliased bitmap text that measures, wraps, paginates and draws exactly like the LVGL 8.3 build Biscuit came from (each game's own fonts in its `generated/fonts.h`, from `tools/fontconv.py`: `--game tiltfc` for Tilt FC's, which keeps bitmaps only for the glyphs it draws), and `font::clip` so a game repainting part of the panel never blends a glyph's edge twice. Physical px; hit tests stay logical, and text logs into the same `gfx::textLog` in logical px so the UI audit covers both surfaces. The firmware renders such a game straight into the panel's back buffer.
- `canvas.h` / `canvas.cpp`: the clipped span painter for RGB565 games drawn in code (Marble Kick, Tilt FC): one span
  writer cut to a clip box (`canvas::clip` also sets `font::clip`), discs, convex polygons, round boxes, and
  `canvas::Frames`, the two-buffer bookkeeping that repaints only the movers that changed (a page's movers as boxes
  with keys, the rest of its state as one `look` word). The look stays in each game.
- `input.h`: turns raw touch samples into tap/long-press/drag edges (`InputTracker`); shared verbatim by firmware and host. `tap` is a press lifted within 8 px of where it began, however long it was held (a user decision of 2026-11-09: kids of 5-7 press for 0.6-3 s, and buttons that ignored that taught them buttons were broken); `longPress` still fires once at 600 ms, and `longTap` marks a tap whose press already fired it, so a target with its own in-place long-press action takes only that (the Admin limit editors' hold of +/-10 or +/-60, Pets Club's long press that pets the dog, and Starfighter's fire, which only quick taps trigger so a hand resting on the glass never acts; Pumpkin's ghost instead acts on the lift of any press, and its action sign hides the pumpkin exactly while a finger that touched it (pressed there, or slid on where it can hide at once) stays down, wherever it drifts; both ignore a press that began before the round did). A hold that changes the screen while the finger is still down (a picker row's 3 s delete) needs nothing: `FreshGate` hides the held finger's lift. A button draws pressed only under a press that began on it (`ui::pressing`), never under a finger slid onto it from another. Tests: `longPressStillTaps`, `slowPresses` in `host/test_shell.cpp`; playtest `tests/playtests/b1_long_presses.txt`.
- `air.h`: the aircraft feed Radar reads (`air::Feed`, set by the host; planes as offsets from home). Header-only.
- `tilt.h`: tilt from however the kid holds the device, for every tilt game: `tilt::from` (gravity turned by the
  rotation that lays the kid's calibrated neutral flat), `tilt::Steady` (the neutral: the average of the last 300 ms,
  refused while a reading is not a plausible 1 g) and `tilt::Follow` (a Calibrate page's slow reference). What a tilt
  does stays in the game. Header-only; `host/test_tilt.cpp`.
- `palette.h`: the fixed 32-color palette and the day/evening/night tint tables. Indexed games only; an RGB565 game picks its own flat colors.

`os/timezone.h` / `.cpp` derive local-wall seconds from a UTC running clock and RTC. The public-domain IANA 2026b catalog (`os/generated/timezones.h`, regenerated offline by `python3 tools/timezones.py --check` from pinned `tools/timezones/tzdata.zi`) has 436 canonical zones and 162 aliases. Known finite UTC transitions take precedence over recurring POSIX tails for 2024–2099; `timezone.cpp` evaluates the tail rule itself (never the C library's `TZ`/`localtime_r`/`mktime`, which the board's newlib and the host's glibc do not implement alike), and `test_timezone` checks it against glibc for every zone to 2100; clock conversion and zone selection stay on the main core. `"sys"/"tz"` is a CRC-validated 76-byte settings blob. `"sys"/"rtc_clock"` is a CRC-validated 20-byte prepared/committed migration journal, subsequently checkpointed hourly in UTC. Missing/corrupt legacy `utc_off` means the old UTC default, while valid saved offsets migrate the old local RTC. A failed prepared write leaves the RTC alone; uncertain recovery uses a UTC checkpoint/build lower bound and lifts daily caps. It never guesses the provenance of mixed historical profile-local timestamps. IP guessing is one serialized radio job using HTTPS `ipapi.co/timezone/`, preceded by time sync for certificate validation; only the public IP is exposed. Failed/invalid replies retain the saved zone; a later successful NTP connection can retry automatically, at most once per six hours. Successful guesses are cached, while network changes and Detect request a fresh guess. Manual changes and network saves invalidate older pending automatic replies. Unit tests: `host/test_clock.cpp`, `host/test_timezone.cpp`; canned network/date regressions are separated from actual play in `docs/family-controls/`.

`firmware/board.cpp`, `firmware/board.h`, `firmware/main.cpp` are the firmware, the only code that includes Arduino headers. `board.h` is the hardware contract (display present/init, touch, the QMI8658 accelerometer as screen-frame gravity (`readAccel`; its chip-to-screen axis table sits next to the driver), RTC, backlight, buzzer, NVS blobs addressed by namespace and key); `board.cpp` implements it for this specific board; `main.cpp` is the Arduino `setup()`/`loop()` that runs the `Shell` with the static `APPS` array over an NVS `Store`, restores the clock, dims the backlight, and feeds the accelerometer's gravity into every frame's `Input`, keeps frame metrics, and parses serial commands. `net.h` / `net.cpp` are wireless updates (`net::Updater`, the `shell::System` implementation): once a local day, while the screen is dark (the backlight at 0), a low-priority task on core 0 joins the saved wifi, reads the channel's newest version from GitHub releases and streams a newer `porthole-<ver>-ota.bin` into the spare OTA slot, which starts on the next power-on. Flash writes interrupt the RGB panel's PSRAM scan-out, so every update check switches to a small internal-SRAM screen (daily checks keep the idle backlight setting; Check now / `U` stays lit): "Checking...", "Downloading N%", "Verifying...", and Cancel ("Stopping..." until cleanup finishes). `firmware/update_gate.h` provides the cross-core handshake: no flash writes begin until the loop has installed the safe display; allocation failure fails the check with the original display intact. `firmware/update_picture.h` draws two banks of centered text and a Cancel label on black. The update picture allocates nineteen separate 3.8 KB internal-DMA chunks, so it does not require one contiguous 73 KB block. Starfighter's scene and packed-image decoder scratch allocate on the heap after PSRAM initialization (Starfighter draws its scene in a `fastmem` loan while lit). A game may borrow internal RAM for one hot buffer while open with `os/fastmem.h`: `take()` lends only while `fastmem::UPDATE_RAM` (the boot check's own sum) and a TLS-sized block stay free, the loop's `fastmem::setDark()` recalls the loan before any update can start (dark or an update screen), and the game gives it back on `leave()`. The firmware builds at `-Os`; the shared painters (`os/canvas`, `gfx`, `gfx565`, `packed_image`) and every game's render files switch themselves to `-O2` with a board-only `#pragma GCC optimize`, as Sand Jar's physics does. A `custom_dram_static_max` build guard keeps static internal RAM below 96 KB and lists its 25 largest symbols in the build log; the games and the shell are built in PSRAM (`os/psram.h`) to stay under it; an OTA boot checks update RAM headroom before validating itself and never marks an insufficient-memory image valid if rollback fails. `firmware/update_scanout.cpp` captures the LCD DMA channel with the scoped `--wrap=gdma_connect` linker hook, then streams circular descriptor lists reusing black rows around those strips (about 76 KB internal RAM). It masks the stock driver's VSYNC restart while active, so cache-disabled interrupts cannot interrupt the autonomous SRAM scan. Progress swaps only at a complete frame boundary, at most four times a second; normal framebuffer scan-out is restored through `esp_lcd_panel_init()` before sparse memory is freed. All switches happen on the loop core that created the driver. Cancel stops at the next network/write boundary (a blocking HTTPS request can take its timeout); an atomic handoff makes cancellation and final verification mutually exclusive; Cancel disappears when verification/boot selection begins. Daily checks start only in the dark; activity stops them at the next network/write boundary. Their SRAM screen stays dark while idle and provides stopping/checking feedback if woken until cleanup finishes. Before lighting a normal dark screen, `board::settlePanel()` waits for a DMA restart and a complete fresh scan; a timeout leaves the backlight off and retries next frame. Ordinary rendering uses 10-row internal bounce buffers and the pinned driver under `firmware/vendor/rgb` (provenance and two local patches in its README): healthy frames are never forcibly restarted, while missed EOFs and explicit recovery still restart from the top with a reset bounce index. `DisplayFrames` in `firmware/display_frames.h` gates buffer ownership: submit and the driver call are atomic with the same-core ISR; only `on_frame_buf_complete`, after the last old pixel was copied into SRAM, acknowledges reuse. VSYNC only serves clean-scan waiting on wake. A missing copy acknowledgment fails closed instead of returning a buffer that could still be read. `gfx565::expandIndexed3()` is the shared single-expansion path for shell/Pets Club and Pumpkin; the latter composes in `gfx::fb` using its own palette, without extra framebuffer allocation. A change to dimming must keep the board going fully dark when idle, or it never updates by itself; NVS namespace `"sys"` keys `ssid`, `pass`, `chan`, `last`, `home` (Radar's center: `shell::Home`'s 112 bytes raw, never resized) (plus the shell's `ran` and `lite`); the Home lookup (`startLookup`) is one more radio job: it joins the saved wifi and sends the typed address once to OpenStreetMap Nominatim (never logged or kept; only the place's coordinates and ASCII-folded name come back). `net::Radar` (`air::Feed`, set in `setup()`) is Radar's feed and the radio's longest job: while Radar is open and the screen lit, a core-0 task holds the radio (`g_busy`: the daily check, Check now and the menu's wifi jobs wait), joins once (`S_NO_WIFI` if it can't, `S_NO_SPOT` with no home, both until Radar starts it again), and every 5 s GETs adsb.fi's `/api/v3/lat/<lat>/lon/<lon>/dist/<nm>` with home rounded to 2 decimals, parsed with ArduinoJson (filtered, pools in PSRAM) into the nearest `air::MAX_PLANES` (ground ones dropped), double-buffered for `read()`; then one uncached callsign's route from adsbdb.com (32-entry cache, 404 cached as none, a route the plane is far off is dropped). It lets go on `stop()` and when the screen goes dark (so the daily update still runs overnight); on waking `read()` says `S_JOINING` and the task starts again. `net::Lan` (`lan::Radio`, set in `setup()`) is Rally's Together link, one more radio job of the same shape: while Rally is open it joins the saved wifi and sends and receives UDP datagrams on port 47800 of the home network (a broadcast while its track cards are open, then to the paired device's address; a 6-slot ring in, one slot out, in PSRAM); power save is off only while it sends, and the clock sync waits until no race is sending; it lets go when Rally closes. Every request is HTTP/1.0 (no chunked body) with a User-Agent naming porthole and the repo, and a failed request logs its URL without the query; the optional SD card (`board::mountSd()`) only supplies `/porthole/wifi.txt`. `setup()` marks a new firmware valid (`verifyRollbackLater()`, loop watchdog until then) after the first frame and before `g_shell.begin()`, so a rollback never meets a save format it can't read. `board::presentHires()` shows the back buffer: a `SURFACE_RGB565` game renders a native 480x480 frame straight into it, an indexed game's 160x160 frame is upscaled 3x into it by `board::expand()`, which rewrites only the logical rows that changed since that buffer last held an indexed frame (`gfx565::Expanded`: a hash per row and the palette; any other drawing into the buffer forgets it).

`host/` is the simulator and the tests: `sim.cpp` (the whole shell; SDL2 window, or headless `--script`/`--serve` modes, where `do <script command>` runs one script line; saves go to `build/host/<namespace>-<key>.sav`; `SimLan` gives Rally's Together UDP on 127.0.0.1, so two sims pair, driven by `tools/together.py`), `test_pet.cpp` (the Pets Club simulation self-check), `test_shell.cpp` (profiles, migration, delete, rest budget, daily cap, launcher layout), `test_biscuit.cpp` (Biscuit's rules self-check), `test_marble.cpp` (Marble Kick's physics, levels, save and drawing), `test_tilt.cpp` (`os/tilt.h`), `test_tiltfc.cpp` (Tilt FC's rules, balance, save and drawing) and `test_pumpkin.cpp` (Pumpkin's rules, a winnability bot over 100 seeds, input gates and drawing), with `grip.h` (the test grips and the inverse of `tilt::from`) shared by the tilt games' tests -- a new game's host test always lives here, as `host/test_<name>.cpp`, not inside the game's own directory. `test_display_frames`, `test_update_gate` and `test_update_picture` exercise the platform-independent update handshake and sparse picture layout in `firmware/`, and `test_touch_hold` the rule that one failed touch read keeps the press (`firmware/touch_hold.h`); no host test depends on ESP32 hardware headers.

`tools/` is dev tooling: `webemu.py` (serves `build/host/snap --serve` in a browser), `playtest.py` (the playtest runner) and `fontconv.py` (an RGB565 game's `generated/fonts.h` from lv_font_conv output, `--game biscuit|tiltfc`; `--game uk` writes `os/uk_fonts.h`, Andika Bold for Pets Club's Ukrainian words).

## Hard constraints

Every change must respect all seven. None of these are stylistic; each one maps to a real failure mode (a save that bricks on the next boot, a button a kid can't reach, a dog that "dies").

1. **Round screen.** The visible area is the circle of radius 80 around (80,80) in logical px (`gfx::CX`, `gfx::CY`, `gfx::R` in `os/gfx.h`; test with `gfx::inCircle(x, y[, margin])`). 1 logical px = 3 physical px = 0.33 mm (160x160 logical -> 480x480 physical). This applies at native 480x480 too: an RGB565 game's own `inCircle` is the same radius-240 circle around (240,240), just unscaled. Anything tappable must be at least 24x22 logical (8 mm) and lie entirely inside the circle: that is the exact size of the four home-screen buttons (`BTN_W=24, BTN_H=22` in `game.cpp`), not a rounded-up guideline. Text must never be cut by the bezel: before placing text at row `y`, compute the chord half-width `sqrt(80^2 - (y-80)^2)` and keep the text's full drawn width inside `[80 - halfwidth, 80 + halfwidth]`.
2. **Flat colors, and only the game's own font's glyphs.** This is per surface. An indexed (`SURFACE_INDEXED`) game: every framebuffer pixel is a palette index 0-31 (`Col` enum, `os/palette.h`) or `C_T` (255, transparent, sprites only) -- never a 33rd color or an out-of-palette blend -- and all text renders through the 8x8 font (`font8x8_basic.h`), ASCII 0-127 only: no curly quotes, no em/en dashes, no accented letters, anywhere a kid sees it. An RGB565 (`SURFACE_RGB565`) game: its art is flat fills and pre-rendered scenes, with no runtime blending beyond what its art tool already baked in -- text is the one exception, blending each glyph's 4-bit coverage against the pixel underneath at draw time -- and every drawn string is limited to its bundled font's actual glyph set -- a content gate rejects anything outside it, the same discipline as ASCII-only, just against a bigger table. Both keep the round-screen and 8 mm tap-target rules above.
3. **The buzzer is harsh.** `board::buzzer()` / `Shell::soundOn()` (the open game's `soundOn()`, gated by the device's Admin sound switch) drive a single-tone piezo. Never wire a sound to routine input (taps, navigation): only to rare, meaningful moments (growth, a trick learned, a gift, a sticker, end of a minigame), and only through the existing `Sound` enum in `game.h`. There is one device-wide sound switch on Admin page 2 (`"sys"/"sound"`); every sound path goes through the shell, which respects it. (Biscuit ships with no sounds at all, by design -- see its own brief.)
4. **A persisted layout is append-only.** Every game's `Save` struct and the shell's profile `Record` (`shell/profiles.h`, `porthole/p<id>`) are raw byte blobs with a magic/version/size/crc header, one per profile, written by the shell (NVS namespace per game, key `s<profile id>`). To add a field: put it immediately before `crc`, bump the version constant, and extend the loader so every older blob size/version still loads. Never reorder or resize an existing field: that corrupts every save already written to a device, silently. Each game's own `AGENTS.md` names its exact fields and the migration pattern already in use there. Kingdom and Times Cards store that struct bit-packed (`os/bits.h`; whole, their saves did not fit): the struct is still the append-only layout, and a new field also joins the game's pack description. All saves share one 20 KB NVS partition, 504 entries of 32 bytes: `host/test_nvs_budget.cpp` fails unless `MAX_PROFILES` kids who have played every game to its end fit next to the device's own keys, and prints what is left to spare (8 entries on 2026-11-16, after telemetry's one key); a new save, or one that grows, has to fit in that.
5. **No game punishes absence.** Pets Club: every stat decays toward a floor and stops (`pet::FLOOR_FOOD`, `FLOOR_FUN`, `FLOOR_ENERGY`, `FLOOR_CLEAN` in `games/pets-club/pet.h`; currently 20/25/20/20), no game over, no running away, no forced reset (moving an old dog to the farm happens only on the kid's confirmed choice, keeps their progress and keeps the dog on the wall); time away is capped at `pet::OFFLINE_CAP_SEC` (12 hours) of decay, and overnight hours count as sleep. Biscuit's contract (see its brief) is the same idea stated more broadly: no death, no guilt for absence, no expiring friendship or streaks, no lost progress. Neither game reads a weekend offline as neglect.
6. **Built for a 5-10 year old.** Short, common words in whichever glyph set the surface allows (constraint 2). Failure is gentle: a wrong answer or a miss shows the right thing and moves on; it never blocks progress or resets state. No dead ends: every screen needs an always-reachable way back (`Game::drawBackButton`/`backButton` or an equivalent visible exit); check this for any new screen.
7. **Have an independent agent play as the target child before calling it done.** Every game's gameplay/UI changes require a final-build black-box emulator playthrough by an independent `playtester`, in addition to `make check` and `make ci`. New games and major changes require a source-free first-play pass. Specify the game's target age, reading ability, experience and imprecise touch/tilt behavior. Use visible controls; explore likely attractions, wrong choices, mis-taps and recovery. Judge boredom, comprehension, meaningful choices and playability, not just completion. Iterate on mechanics, controls, player-facing instructions and the playtester's brief, then replay the affected flow after fixes until acceptance in `docs/playtesting.md` is met. Preserve the persona/brief, final build, findings/resolutions, native screenshots and input evidence. Follow that procedure and the `playtest` skill; the implementer's own run, unit tests, bots and debug tours do not replace the independent pass. An unplugged board is not an exemption. Documentation-only and non-player-visible changes need no new playthrough.

Note on constraint 6 and learning: a mechanic that teaches (maths, reading, memory) follows `docs/design/learning-principles.md`, which says what the research supports for ages 6 to 8 and gives a checklist for choosing the next mechanic; the plan for adaptive levels and spaced review in Biscuit and Times Cards is `docs/design/adaptive-practice.md`.

Note on constraint 1 and automated checks: `make playtest`'s UI audit fails a run on any finding. It still labels a target under 18 logical px (6 mm) FAIL and one under the real 24x22 (8 mm) box WARN, but warnings are errors: a WARN fails the run just like a FAIL. One scoped exception, a user decision of 2026-10-18: the grown-ups' system menu screens (`GROWN_UPS` in `tools/playtest.py`: `sys_info`, `sys_updates`, `sys_wifi`, `sys_pass`, `sys_join`, `sys_home`, `sys_addr`, `sys_find`, `sys_admin`, `sys_pin`, `sys_pin_set`, `sys_pin_again`, `sys_reset`, `sys_remove`, `sys_players`, `sys_player_pin`, `sys_limits`, `sys_clock`, `sys_time`, `sys_window`, `sys_allow`, `sys_zone`, `sys_zone_search`, `sys_games`; not the kids' `sys_new` card) take 18 px targets without the 24x22 WARN, and use native-resolution anti-aliased adult typography instead of the indexed 8x8 font (a user readability decision of 2026-10-19; constraints 1 and 2). Every other rule, the 18 px FAIL included, still holds there, except on the keyboards (`KEYBOARDS`: `sys_pass`, `sys_addr`, `sys_zone_search`), whose QWERTY keys may be 12 px wide.

Note on constraint 2 and content: Pets Club's `games/pets-club/tools/check_content.py` re-renders every string through the real 8x8 font and word-wraps it into the exact box the game draws it in -- the source of truth, not a character count. Biscuit's gate is two parts: `games/biscuit/tools/check_content.py` (in `make lint`) checks the glyph set (read from `generated/fonts.h`), token validity, counts and ids; `host/test_biscuit_content.cpp` (in `make test`) measures and draws every string with `os/font.cpp` itself, tokens filled with the widest names (11 and 12 W's), in the box `games/biscuit/layout.h` gives its screen, and fails on text taller than its box or ink off the round glass; a story up to its choice, an ending or a discovery is its pages filled and joined with a space into one text (`Game::openPages`) and flowed onto screens of the 352x176 font24 page box, at most `READ_BYTES` filled and `READ_SCREENS` screens (`layout.h`), the last screen holding at least `MIN_LAST_WORDS` words at the widest names and at short ones (Sam/Pip). See the `content` skill.

## Workflows

### make targets (Makefile)

The repo root and CI call these by name; keep them working:

- `make lint`: app-specific static checks: `games/pets-club/tools/check_content.py`, `games/pets-club/tools/art.py --check`, `tools/shell_art.py --check`, `tools/timezones.py --check` (the generated timezone catalog against its pinned tzdata; needs the system `zic`), `games/biscuit/tools/check_content.py`, and a `-Werror` host build of the shell, the games and the sim. (ruff and shellcheck run from the repo-root pre-commit, not here.) Biscuit's art tool's `--check` also runs here, skipped with a message where `node` is missing (CI's runner always has it).
- `make check`: `lint` + `test`. What pre-commit runs; a few seconds.
- `make ci`: `lint` + `test` + `test-asan` (the same tests under AddressSanitizer + UBSan, minus the long `test_racing_rules`; `test_saves` there plays every game in `APPS` on junk, cut-short and crc-valid changed saves, and a new saving game gets a line in its `base()`) + `coverage` + the sanitizer monkey playtests (`make playtest-monkey`) + the build of the windowed `sim` where SDL2 is installed (CI installs it), everything CI runs for this app except the firmware build. `coverage` plays every other scenario, so none plays twice. Every build is incremental and parallel (`NPROC=1` for serial output).
- `make coverage`: builds every `test_*` binary and `snap` with `--coverage` under `build/coverage/`, runs all the tests plus the non-monkey playtests, and writes line coverage of `os/`, `shell/` and `games/*/` (sources and headers, a template counted once however many games use it) and of the firmware headers the host builds to `build/coverage/coverage.xml` (Cobertura, via gcovr). Fails below `COV_MIN` in the Makefile, and prints how many lines of `firmware/*.cpp` (board-only) it cannot see. On macOS gcovr uses `xcrun llvm-cov gcov`; elsewhere `gcov`. Uses `gcovr` 8.3 or newer from PATH, else `uvx` fetches one.
- `make firmware` / `make flash [PORT=...]` / `make monitor [PORT=...]`: `pio run -e firmware`, upload, and the 115200-baud serial monitor. PlatformIO auto-detects the port when `PORT` is not given.

Development targets:

- `make sim`: SDL2 window. Mouse = finger. Keys: `h` +1 hour, `n` +8 hours, `d` +1 day, `r` reset save, `s` screenshot to `build/host/shot.bmp`, `p` print stats to stdout, `b` next brightness, `q`/Esc quit.
- `make snap`: headless binary, no SDL, two modes:
  - `./build/host/snap --script FILE` runs a command script (see the `tour` skill) and writes named `.bmp` files to `build/host/`.
  - `./build/host/snap --serve` speaks the stdin/stdout protocol `tools/webemu.py` drives.
  - Both accept `--now EPOCH` (fixed clock) and `--fresh` (wipe saves first); the default clock is a fixed Tuesday 16:00 local time, so unscripted snapshots are still deterministic.
- `make snap-asan`: the same headless binary built with AddressSanitizer + UBSan. Used by the chaos-monkey playtest scenarios; slower, build it only when you need sanitizer coverage.
- `make test`: builds and runs every `host/test_*.cpp` the Makefile auto-discovers, each against its own `test_<name>_SRC :=` source list: `test_pet` (`os/*.cpp`, Pets Club's `pet.cpp` and `game.cpp`), `test_shell` (`shell/profiles.cpp`, `shell/migrate.cpp`, Pets Club's `pet.cpp`), `test_biscuit` (Biscuit's rules -- header-only, no extra sources), `test_biscuit_content` (`os/*.cpp`, `games/biscuit/personalize.cpp`, `games/biscuit/art.cpp`: `personalize()`, the generated art tables, and Biscuit's pixel content gate: every string, tokens filled with the widest names, measured and drawn by `os/font.cpp` in the box `games/biscuit/layout.h` gives its screen and inside the round glass), `test_gfx565` (`os/*.cpp`: the RGB565 surface and fonts), `test_marble` (`os/*.cpp`, `games/marble-kick/*.cpp`: the tilt mapping from any grip, the ball staying on the tray, no tunneling, rails, defenders, holes, stars and moving goals, no ball-sized gaps and no resting spot a tilt cannot free, a greedy tilt at the goal failing from level 3 on, goals, the save and its v1 migration, every level's recorded solution replayed to a goal from three grips and kept in step with the playtests' `# solution` blocks (`build/host/test_marble --write-playtests`; `--levels` reports every level's design checks), and every incrementally drawn frame equal to a full repaint), `test_tilt` (`os/tilt.h`, header-only), `test_tiltfc` (`os/*.cpp`, `games/tilt-fc/*.cpp`: the dead zone from any grip, pass targeting in the cone, control switching, goals, kickoff, tackles, the whistle, the challenge -- a greedy player against one who passes and aims, and an idle one, thirty seeded matches each per level, each level no easier than the last within seed noise and the top level harder than the first --, the save, every drawn string in the font, every incrementally drawn frame equal to a full repaint, and the playtests' recorded `# match` blocks in step with the rules: `build/host/test_tiltfc --write-playtests`). Self-checks without a window: `test_marble` and `test_tiltfc` render, into memory. Must stay green. Every host build (the coverage objects too) compiles with `-ffp-contract=off`: the seeded float replays and balance numbers then come out the same under Apple clang (which fuses FMAs by default) and CI's gcc.
- `make webemu`: depends on `snap`; runs `tools/webemu.py`, serves the game at `http://127.0.0.1:8765` (`python3 tools/webemu.py 8766` for another port). The buttons under the canvas skip time and force debug states for testing.
- `make web`: the same sim through Emscripten (`em++` from emsdk on PATH) into `build/web/porthole.{js,wasm}`; `host/sim.cpp` exports `web_cmd` (one `--serve` command) and `web_frame` (the panel as RGBA). `.github/workflows/pages.yml` builds it on every deploy twice, this commit into `site/play/beta/` and the stable release's tag into `site/play/stable/` (only once that tag has `make web`), for the player on the home page (`site/index.html`, whose Stable and Beta buttons pick one; it gets the commit for `__BUILD__` and the stable version for `__STABLE_PLAY__`; `/play/` only redirects there). The page drives either build with the same `--serve` commands, so keep those working for older builds. It starts on a tap, on a Guest profile's launcher (a board still asks for a profile); saves live in the page's memory until a reload. On a phone it opens full screen and feeds the phone's own motion sensor in as the board's (the phone button in the player's corner; Android turns it on by itself, iOS asks), turned for landscape; once on, that button is `Center`, which makes the current grip upright or flat. Without one the tilt is the dark rim (pressing it tips the board toward the finger, letting go lays it flat) or the held arrow keys. Shake, full screen and start over sit in the other corners, so the player never changes the page's layout.
- `make art`: runs `games/pets-club/tools/art.py`, `tools/shell_art.py`, and Biscuit's Node-based art tool (`node games/biscuit/tools/art/export-assets.mjs`, Node 22 from `/.tool-versions`, zero npm deps), regenerating `games/pets-club/sprites.h`, `shell/shell_sprites.h` (and, if Pillow is installed, preview sheets under `build/art/`), and `games/biscuit/generated/{scenes.h,discovery_art.h,art_data.inc,manifest.json}` from committed JS sources. All have `--check`, which `make lint` runs (Biscuit's skipped with a message if `node` is missing, an error with `REQUIRE_NODE=1`, which CI sets) -- see the `art` skill.
- `make playtest`: depends on `snap` and `snap-asan`; runs `python3 tools/playtest.py` against every scenario in `tests/playtests/*.txt`, writes `build/playtest/report.md` plus a contact-sheet PNG per scenario. See the `playtest` skill for how to read the report.
- `make clean`: removes `build/` (not `.pio/`, the firmware build cache).

### Firmware build and flash

```bash
make firmware                                  # pio run -e firmware
make flash                                     # or: make flash PORT=/dev/cu.usbmodemXXXX (Linux: usually /dev/ttyACM0)
make monitor
```

`platformio.ini` extends `[waveshare_round]` from `../../platform/waveshare-round.ini` (platform pin, board, PSRAM and USB flags) and adds only the app specifics (source dirs, partition table, upload speed, warning flags, `-Ios -Ishell -I.`). The env is `firmware`. The partition table is `partitions.csv`: nvs at 0x9000 (unchanged from PlatformIO's default, so saves survive a reflash), otadata, two 7.9 MB OTA app slots (`ota_0` at 0x10000, `ota_1` at 0x800000; `board_upload.maximum_size` = one slot, 8323072, so the build fails before firmware outgrows a slot), coredump. `make flash` also writes `boot_app0.bin`, which selects `ota_0`, so a USB flash boots what it wrote even on a board an update moved to `ota_1`.

See the `flash` skill for the PlatformIO-venv Python-dependency caveat and how to set the clock.

### Serial commands (`main.cpp` `loop()`, 115200 baud)

They work on either USB-C port: `firmware/console.h` (included by `board.h`) redefines `Serial` as a console that writes to both UART0 (the CH343 "USB to UART" port) and the ESP32-S3's own USB-Serial-JTAG port, and reads from whichever has bytes.

| Command | Effect |
| --- | --- |
| `S` | Print the active profile and the stats of every game opened since boot, the open (or last) one last (`Shell::debugPrint()`), plus NVS entries (`nvs_used= nvs_free=`: saves fail once the partition is full), the least the 8 KB loop stack ever had left (`stack_free=`, bytes), free heap, current epoch, and `version= slot= update=<UpdState> pct= available= last_check=` |
| `T<epoch>` | Set the RTC and running clock to `<epoch>` (local wall-clock seconds; ignored if <= 1,600,000,000) |
| `RESET` | Erase every profile and every game's saves (namespaces `porthole` and each app's store), then reboot. The whole word on its own line: a lone `R`, or `R` followed by anything else, only prints the usage |
| `P<n>` | Clear profile `n`'s 4-digit secret code (parent escape hatch) |
| `D` | Toggle touch-position logging |
| `A` | Print the accelerometer: raw chip axes (LSB, 8192 = 1 g) and the mapped gravity `gx,gy,gz` (milli-g, screen frame, what `Input` gets) |
| `G<x>,<y>,<z>` / `G` | Hold `Input`'s gravity at that vector (milli-g, screen frame, each axis clamped to the sensor's +-4000) for testing; a bare `G` returns to the sensor (`devctl.py tilt X Y Z` / `untilt`; `devctl.py run` always ends with one) |
| `M` | Frame metrics over the last 64 frames: loop period and fps (plus the worst frame), time in shell update, render (an indexed frame's 3x expansion included) and present (the wait for the driver to take the frame; `present_max=` is the longest since boot, and over 250 ms means a late frame ack restarted the panel), failed touch reads since boot (`touch_miss=`), free heap, free PSRAM, largest free internal block (`devctl.py metrics`; `devctl.py fps` repeats it with the screen's name while you play) |
| `W<ssid>\t<password>` | Save the wifi network to NVS `"sys"` (the tab is required; nothing after it = an open network) |
| `L<lat>,<lon>` | Save Radar's home (decimal degrees) to NVS `"sys"/home` without the menu's address lookup |
| `U` | Check for an update now and download it (any build; a "dev" build checks but never downloads); says "dropped" when a run or a wifi scan/test holds the radio or an update is ready |

### Hooks and CI

Hooks are managed by the repo-root pre-commit config, not by this app: it runs ruff and shellcheck repo-wide and `make -C apps/porthole check` for this app. CI runs `make ci` plus the firmware build. Run `make ci` yourself before pushing anything that touches gameplay or UI; a red CI run is a worse time to find out.

## Model policy

**opus** for anything that writes or reviews code, or judges design/polish: `game-designer`, `game-engineer`, `firmware-engineer`, `pixel-artist`, `playtester`, `reviewer`.
**sonnet** for prose and bounded research: `story-writer`.
**haiku** for mechanical sweeps (renames, formatting, single-file lookups): no standing agent above is haiku; reach for it directly, ad hoc, for that class of task.

State the model when dispatching an agent (for example: "dispatching `game-engineer` (opus) to implement this"). Between sonnet and opus for anything code-shaped, take opus.
