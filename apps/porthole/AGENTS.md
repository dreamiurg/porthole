# Porthole: agent brief

## What this is

Porthole is the device firmware: a shared runtime (`os/`), the board layer (`firmware/`), the shell (`shell/`: "Who's playing?", up to four profiles, the launcher, the rest timer) and the games compiled into one image (`games/`). Its first game is Pets Club. The second, Biscuit, was rewritten onto this same runtime (it previously shipped as a standalone LVGL firmware and was removed in PR #24), with full content parity. Design: `docs/superpowers/specs/2026-09-24-launcher-profiles-design.md` (shell/profiles) and `docs/superpowers/specs/2026-09-25-biscuit-on-porthole-design.md` (Biscuit) at the repo root.

Pets Club is a touch-only, Tamagotchi-style dog companion for the Waveshare ESP32-S3-Touch-LCD-2.1, a round 480x480 capacitive-touch panel with no physical buttons. It is built for kids aged 5-10 who like reading and dogs: the pet grows over real calendar days, learns eight tricks over three lessons each, and is read twenty-plus original stories from a library that unlocks with daily gifts. Each profile on the device has its own pet, room and reading level (from the profile's age); Paw Street shows every profile's house. Everything renders into a 160x160 indexed-color framebuffer (32-color palette) that gets upscaled 3x to the physical panel. The pet never dies, never runs away, and never resets: stats decay toward floors, not through them. Its own brief, with the Save layout and reading-level tables: `games/pets-club/AGENTS.md`.

Biscuit is a warm, doglike reading and discovery companion on the same panel, drawn full-color at native 480x480 instead of Pets Club's indexed look. Its product contract, module map and content limits: `games/biscuit/AGENTS.md`.

It lives at `apps/porthole/` in the porthole monorepo (apps for this board sharing build/test/deploy infrastructure). Every path below is relative to `apps/porthole/`, and every command runs from there (or as `make -C apps/porthole <target>` from the repo root). The shared PlatformIO board base is `../../platform/waveshare-round.ini`. Read a game's own `AGENTS.md` before touching it; this file covers what every game shares.

## Architecture map

`os/`, `shell/` and each game under `games/<game>/` are the platform-agnostic core. They compile unchanged into both the firmware and the host simulator (`-DHOST_BUILD` only changes what `main()` exists, not the game logic). The include path is `-Ios -Ishell -I.`: `os/` and `shell/` headers by bare name, a game's own headers by bare name (same directory), and a game's headers from anywhere else by path (`games/pets-club/game.h`). `os/` never includes anything from `shell/`, `games/` or `firmware/`; games include only `os/`; the shell knows games only through `os/app.h` (one exception: `shell/migrate.cpp` reads a game's old save layout once, for a one-time migration -- Pets Club's old houses today, Biscuit's old NVS blob once its migration lands).

In `shell/`:

- `profiles.h` / `profiles.cpp`: the profile record (`porthole/p<id>`, append-only with magic/version/size/crc, `MAX_PROFILES = 4`, currently version 2 / 52 bytes, `REC_V1_SIZE = 44` still loads), create/delete (delete erases `s<id>` in every game's namespace), the per-session rest budget (parent-configured minutes, default `SESSION_SEC`; `REST_SEC` break, even with one player), the daily play cap (parent-configured minutes, default `DAILY_SEC` = 30 min per profile per local day, across every game, kept as `(playDay, dayPlaySec)` rather than a deadline so a new day or a clock set back just resets it -- `playedToday()`/`restLeft()` read it, `shell::play()` updates it), `IDLE_MS` (a minute without activity counts toward neither budget; also the firmware's first backlight-dimming step. Activity is a touch or a move of the board -- gravity more than `ActivityTracker::MOVE_MG` = 200 mg from where it was at the last activity -- so hands-off tilt play counts and a board lying still does not; `ActivityTracker` in `os/input.h` is the one rule, the shell and the firmware's dimming each run one, and a move wakes a dark screen without becoming a touch. A product decision, not an oversight: any move over 200 mg counts, a car ride, a bag or a bumped nightstand included. That is the conservative side for the daily cap (more time counts, never less), it keeps the screen lit while the board is being carried, and at bedtime (`asleep()`) a bump lights the screen at 40% for 20 s and nothing more), `liftCaps` (called from `Shell::clockRestored()` when the firmware had to guess the clock after losing the RTC: "today" cannot be trusted -- every cap lifts, like a clock set back), and the `Store` interface both platforms implement. `host/test_shell.cpp` exercises it directly.
- `migrate.cpp`: first boot on a Pets Club device: house `crago/s<n>` becomes profile `n` (same slot, no save moves; the older `save` key is copied to `s0` only when no house exists). Runs until the marker `porthole/m` is written, so power loss mid-migration just re-runs it. `migrateBiscuit` does the same once for Biscuit's pre-Porthole save (`zoegotchi/pet3|pet2|pet1` or `biscuit/pet1` -> `biscuit/s<id>`, marker `porthole/mb`); `loadAll` runs it after the Pets Club migration.
- `shell.h` / `shell.cpp`: the `Shell` class: picker, new profile (name, face, age, code), code pad, delete, launcher (mute lives here, and the brightness: see below), rest screen ("Back in N min" for a turn-taking rest, or "Back tomorrow" once `playedToday()`, with no countdown), and hosting the open game (`App`): it writes the game's save at most every 5 s (an `App::saveUrgent()` checkpoint after at least 1 s) and on leaving, never rewrites bytes identical to what it last wrote or loaded, and retries a failed write from its own copy at that cadence, and gates the buzzer with the profile's mute. `dbg bedtime` (see the `tour` skill) uses up today's budget for testing; `debugPrint()`'s `today=` key reports seconds played today.
- Brightness (`shell::Light`, one per device, one byte in NVS `"sys"/"lite"`, the shell's second `"sys"` key; missing or out of range is Auto): the launcher's sun button (`launcher::LIGHT`, right of the header, which is narrowed to fit it and still holds the widest 8-letter name) opens the `light` screen: three suns, big to small, for Bright / Medium / Soft, and Auto (a sun and a moon) under them; a tap picks, saves and returns to the launcher (two taps in all; the home button leaves it unchanged). The sun button shows the level picked. Auto is the old behavior: `clockTint`, a full backlight. Bright / Medium / Soft are always daylight -- `Shell::tint()` is `TINT_DAY` on every shell screen (the rest screen too), and a game gets `AppEnter::daylight` and returns `TINT_DAY` with day scenes (Biscuit's rooms, Pets Club's window and Paw Street); a game's own night (a pet asleep) still holds -- at `shell::LIGHT_BACKLIGHT` 100 / 65 / 40 %. `Shell::backlight()` is that active level; `shell::backlightFor(asleep, idleMs, active)` (`shell.h`, tested in `host/test_shell.cpp`) is the whole rule `dimWhenIdle()` in `firmware/main.cpp` applies: the active level, 30 % after `IDLE_MS`, dark after 5 min, and a game `asleep()` 40 % then dark after 20 s, the same at every level (the updater needs the dark). The `Light` values are persisted: append only, before `LIGHT_COUNT`. Sim: snapshots show the active backlight (`dimmed()` in `host/sim.cpp`), `dbg light` or the window's `b` key picks the next level, `debug` prints `bright=` and `backlight=`, a `reboot` keeps it. Playtest: `tests/playtests/24_brightness.txt`.
- `launcher.h`: the launcher's geometry as pure functions, for up to `MAX_APPS` (12) games: six to a page in two rows of three 40x30 picture tiles (a short last row centered), so ten games are two pages, behind arrows beside the mute button. Each tile shows its game's `App::icon()`, a 38x28 picture in the shell palette that every game generates from `games/<game>/art/launcher.png` with `tools/launcher_icons.py` (Codex art; principles and prompts in `docs/launcher/README.md`). Names are not drawn under tiles: a finger on a tile shows its game's name in a yellow caption over the header row (`CAPTION`). The sim asserts at boot that every game's name fits the caption and its picture fits a tile, so a long name or a big icon fails `make playtest`. The light screen's three suns keep their own 44 px row (`sun(i)`). `host/test_shell.cpp` holds every layout to the round glass and pages through a `Shell` with stub games.
- `system.h`: `shell::System`, the device side of wireless updates as the shell sees it (`info()`, `status()`, `checkNow()`, `restart()`, the Stable/Beta channel), the `UpdState` states (`UP_COUNT` last, for tables), and `parseVersion`/`newer` (only strictly newer real releases; "dev" never). Its wifi half: `startScan`/`scanResult` and `startTest`/`testResult` (-1 while running), `saveWifi` (a resting "No wifi" or "Check failed" goes back to idle: it was about the old network), and `addNetwork` (the scan list). The radio does one job at a time: a scan or a test is refused while the update check runs, and Check now or the daily check does nothing while a scan or a test runs; the firmware runs each as a task on core 0 and turns wifi off after it. Firmware implements it in `firmware/net.cpp`, the sim with a canned `SimSystem`. Design: `docs/superpowers/specs/2026-10-17-wireless-updates-design.md`.
- `sysmenu.cpp`: the "something new" card (`sys_new`, once on the first boot of a new version: `shell::newRun` compares the running version with `"sys"/ran`, a shell-owned `"sys"` key (alongside `lite`, `admin` and `limits`); "dev" never shows it) and the grown-ups' system menu, reached by holding the picker's title 5 s (only with a `System`): Info (`sys_info`: version, slot, reset reason, heap, SD, wifi; buttons Wifi, Updates and, on a build with a lookup (`System::hasHome`), Home), Updates (`sys_updates`: channel switch, locked while checking, downloading or ready; Check now, hidden while a wifi scan or test holds the radio; Restart now, which needs no radio) and Wifi: `sys_wifi` (a scan's networks, strongest first, one per name, no hidden ones, 4 a page, signal bars and a lock; Rescan), `sys_pass` (a secured network's password on a full QWERTY keyboard, a user decision of 2026-10-18: rows of 10, 9 and shift + 7 + backspace, then page, space and OK; three pages of 26 -- letters with a shift lock, digits and symbols, more symbols; keys of 12x18 px (4 x 6 mm, `KEYBOARDS` in `tools/playtest.py` lets them under the 18 px floor), every tap going to the nearest key and the key under the finger shown big above it; any printable ASCII up to 64; shown as `*` but the last letter, never whole), `sys_join` (a test join with the typed password, which is saved only if it joins; Try again keeps the typing, Save anyway saves it untested; an open network skips the keyboard; while the radio is busy, an update included, it waits ("Waiting for the update") and then tests; a failed save says "Could not save" with Try again), and Home, where Radar centers, one per device: `sys_home` (the place set, or "nothing yet"; Set address), `sys_addr` (the address on the same QWERTY keyboard, shown in full), `sys_find` (the lookup, a radio job like a scan that waits for the radio; "Is this home?" with the place found, saved only on Yes; No and "Could not find that address" go back to the typing, kept; a failed save says so). The address is sent once, to the geocoder, when OK is tapped; only the coordinates and the place's town, region and country are kept, never the street address (`System::home`/`saveHome`; the firmware asks Nominatim for `addressdetails` and keeps those three). The menu is for grown-ups, a user decision of 2026-10-18: it renders at native 480x480 with anti-aliased Atkinson Hyperlegible Regular (`shell/adult_fonts.h`, bundled SIL OFL font under `shell/fonts/`), with 18 logical px (6 mm) targets instead of the kids' 24x22 buttons. Body text is 24 physical px, headings 28 px and keypad digits/key previews 32 px; labels use the same font metrics for measuring, fitting and drawing; `sys_new` is the kids' and keeps their rules. Shell palette only, no sound. `shell::addNetwork` (`system.h`, the scan list) and `shell::TextEntry`/`textKey` (`shell.h`, the keyboard's editing) have unit tests in `host/test_shell.cpp`. Sim script: `sys version V | newest V | nowifi | current | download PCT | ready | failed`, for wifi setup `sys scan | scanempty` (the running scan ends with canned networks, or none) and `sys joinok | joinfail` (the running test join ends so), `sys savefail` (the next save fails), for Home `sys found | notfound` (the running lookup ends so), `sys homefail` (the next save fails), `sys nohome`, and `reboot`; `debug` prints `sys_*` keys (the sim's `sys_pass` is the saved password, host only). Playtests: `tests/playtests/19_system_menu.txt`, `tests/playtests/24_wifi_setup.txt`, `tests/playtests/25_home.txt`.
- Admin controls (`sysmenu.cpp`): the five-second picker-title hold asks for an optional device-wide four-digit code before Info (`sys_pin`); every return to the picker ends access, and a reboot asks again. With a code set, the picker's New and long-press delete ask for it too (`sys_pin`, then the name keyboard or the delete screen; back returns to the picker), so a fresh or deleted profile cannot dodge the limits; the grown-up's code replaces the kid's for delete. Info -> Admin (`sys_admin`) offers Set / Change code (masked, confirmed twice: `sys_pin_set` / `sys_pin_again`) and Remove code (`sys_remove`, confirmation). The separate uint16_t `"sys"/"admin"` stores `pinCode`, 0 or missing = off; writes are read back. Player PINs (`sys_players`) maps each row through `nth()` to its stable id and confirms (`sys_player_pin`) before removing only that player's PIN; failed save readback restores the prior record. Admin has Screen time (`sys_time`), which consolidates session and daily allowances (defaults 15/30 minutes, range 1..1440, tap +/-1 or hold +/-10), the optional play window (`sys_window`, enabled by default 14:00 inclusive–19:30 exclusive, supports overnight), Reset usage (`sys_reset`, confirmed) and Allow 30 min (`sys_allow`, confirmed, can end early). The single-limit editor is `sys_limits`. Editors save explicitly; Back discards. Existing `"sys"/"limits"` stays four bytes and existing values survive updates; `"sys"/"window"` is a separate versioned eight-byte blob. Reset clears each used profile's `restUntil`, `playSec` and `dayPlaySec`, preserving settings, lastPlayed, codes and game saves. A RAM-only monotonic allowance bypasses session/daily/window gates while continuing usage; expiry or reboot restores the rules. Merely entering Admin or resetting usage never grants an allowance. All child entry points, launchers and running games enforce the schedule, with game save flush before stopping. Session limits apply even to a single player, followed by the existing ten-minute rest. Admin page 2 has Clock (`sys_clock`), which shows local time and sync status; named IANA zones (`sys_zone`, searchable via `sys_zone_search`) replace UTC-offset editing. Default America/Los_Angeles, bundled daylight saving rules, saved manual precedence over automatic public-IP guessing, and last-valid fallback when offline. Network time corrects UTC; games use derived local time and play duration uses monotonic milliseconds. Design/state contract: `docs/design/family-screen-time.md`; final black-box evidence: `docs/family-controls/README.md`.
- `shell_sprites.h`: AUTO-GENERATED by `tools/shell_art.py` (avatars, plus, lock, sound icons, and `SPR_LIGHTS`: the brightness suns in `shell::Light` order). `adult_fonts.h`: AUTO-GENERATED by `tools/fontconv.py --game adult` from the bundled Atkinson Hyperlegible font; the source, license and regeneration instructions live under `shell/fonts/`.

Each game lives at `games/<game>/` and owns its own `AGENTS.md` with its Save layout, content limits and any game-specific detail; this file only covers what every game shares.

Each game also owns its look (root `AGENTS.md`, rule 7). `os/palette.h` is the palette Pets Club and the shell's indexed UI share, not a default for new games: a new game draws on the RGB565 surface with its own colors, fonts and art (or first proposes a per-game palette in `os/`), and never reuses another game's sprites, palette or style.

A game is a directory under `games/`: the Makefile and PlatformIO build every `games/*/*.cpp`, so adding one means the directory, an `App` subclass, its launcher picture (`art/launcher.png`, added to `GAMES` in `tools/launcher_icons.py`), and a `static` instance appended to `APPS[]` in `games/apps.h`, the one table the firmware and the sim both run (a `static_assert` holds it to `MAX_APPS`); its `screenName()` values must not repeat another game's or the shell's (`tools/playtest.py` fails on a clash; prefix them). A host test is `apps/porthole/host/test_<name>.cpp` plus one `test_<name>_SRC :=` line in the Makefile -- host tests live in the shared `host/` directory, named per game, not inside the game's own directory.

In `os/`, the shared runtime:

- `app.h`: the contract between the shell and a game (`App`, `Profile`, `SaveSlot`, `AppEnter`, `MAX_PROFILES`, and `enum Surface { SURFACE_INDEXED, SURFACE_RGB565 }` plus `App::surface()`, defaulted to `SURFACE_INDEXED` so Pets Club needs no change; polled every frame, so a game may switch per screen).
- `ui.h` / `ui.cpp`: the shared widgets (panel, button, icon button, the orange back button, toast, the name keyboard, `FreshGate`: every screen change ignores touches for 450 ms), and the press-and-hold rule for a way out a hand on the case may brush during play (`pressing`, `HOLD_MS`, `Hold`: counted from when the finger is on the sign). Stay indexed even on an RGB565 game: launcher, picker, rest screen and this keyboard are always drawn by the shell.
- `crc32.h`: the checksum every persisted blob uses.
- `gfx.h` / `gfx.cpp`: the indexed-color renderer. A 160x160 indexed-color framebuffer (`gfx::fb`), drawing primitives, the 8x8 font, the round-mask test (`gfx::inCircle`), and the `UiAudit` hit-region log / text-box log that the `ui` sim command and the playtester agent read.
- `gfx565.h` / `gfx565.cpp` and `font.h` / `font.cpp`: the full-resolution surface for games whose `App::surface()` is `SURFACE_RGB565`: 480x480 RGB565 primitives, image and RLE blits, and anti-aliased bitmap text that measures, wraps, paginates and draws exactly like the LVGL 8.3 build Biscuit came from (each game's own fonts in its `generated/fonts.h`, from `tools/fontconv.py`: `--game tiltfc` for Tilt FC's, which keeps bitmaps only for the glyphs it draws), and `font::clip` so a game repainting part of the panel never blends a glyph's edge twice. Physical px; hit tests stay logical, and text logs into the same `gfx::textLog` in logical px so the UI audit covers both surfaces. The firmware renders such a game straight into the panel's back buffer.
- `canvas.h` / `canvas.cpp`: the clipped span painter for RGB565 games drawn in code (Marble Kick, Tilt FC): one span
  writer cut to a clip box (`canvas::clip` also sets `font::clip`), discs, convex polygons, round boxes, and
  `canvas::Frames`, the two-buffer bookkeeping that repaints only the movers that changed (a page's movers as boxes
  with keys, the rest of its state as one `look` word). The look stays in each game.
- `input.h`: turns raw touch samples into tap/long-press/drag edges (`InputTracker`); shared verbatim by firmware and host.
- `air.h`: the aircraft feed Radar reads (`air::Feed`, set by the host; planes as offsets from home). Header-only.
- `tilt.h`: tilt from however the kid holds the device, for every tilt game: `tilt::from` (gravity turned by the
  rotation that lays the kid's calibrated neutral flat), `tilt::Steady` (the neutral: the average of the last 300 ms,
  refused while a reading is not a plausible 1 g) and `tilt::Follow` (a Calibrate page's slow reference). What a tilt
  does stays in the game. Header-only; `host/test_tilt.cpp`.
- `palette.h`: the fixed 32-color palette and the day/evening/night tint tables. Indexed games only; an RGB565 game picks its own flat colors.
- `font8x8_basic.h`: third-party public-domain font table, not normally touched.

`os/timezone.h` / `.cpp` derive local-wall seconds from a UTC running clock and RTC. The public-domain IANA 2026b catalog (`os/generated/timezones.h`, regenerated offline by `python3 tools/timezones.py --check` from pinned `tools/timezones/tzdata.zi`) has 436 canonical zones and 162 aliases. Known finite UTC transitions take precedence over recurring POSIX tails for 2024–2099; clock conversion and C-library TZ selection stay on the main core. `"sys"/"tz"` is a CRC-validated 76-byte settings blob. `"sys"/"rtc_clock"` is a CRC-validated 20-byte prepared/committed migration journal, subsequently checkpointed hourly in UTC. Missing/corrupt legacy `utc_off` means the old UTC default, while valid saved offsets migrate the old local RTC. A failed prepared write leaves the RTC alone; uncertain recovery uses a UTC checkpoint/build lower bound and lifts daily caps. It never guesses the provenance of mixed historical profile-local timestamps. IP guessing is one serialized radio job using HTTPS `ipapi.co/timezone/`, preceded by time sync for certificate validation; only the public IP is exposed. Failed/invalid replies retain the saved zone; a later successful NTP connection can retry automatically, at most once per six hours. Successful guesses are cached, while network changes and Detect request a fresh guess. Manual changes and network saves invalidate older pending automatic replies. Unit tests: `host/test_clock.cpp`, `host/test_timezone.cpp`; canned network/date regressions are separated from actual play in `docs/family-controls/`.

`firmware/board.cpp`, `firmware/board.h`, `firmware/main.cpp` are the firmware, the only code that includes Arduino headers. `board.h` is the hardware contract (display present/init, touch, the QMI8658 accelerometer as screen-frame gravity (`readAccel`; its chip-to-screen axis table sits next to the driver), RTC, backlight, buzzer, NVS blobs addressed by namespace and key); `board.cpp` implements it for this specific board; `main.cpp` is the Arduino `setup()`/`loop()` that runs the `Shell` with the static `APPS` array over an NVS `Store`, restores the clock, dims the backlight, and feeds the accelerometer's gravity into every frame's `Input`, keeps frame metrics, and parses serial commands. `net.h` / `net.cpp` are wireless updates (`net::Updater`, the `shell::System` implementation): once a local day, while the screen is dark (the backlight at 0), a low-priority task on core 0 joins the saved wifi, reads the channel's newest version from GitHub releases and streams a newer `porthole-<ver>-ota.bin` into the spare OTA slot, which starts on the next power-on. Flash writes interrupt the RGB panel's PSRAM scan-out, so every update check switches to a small internal-SRAM screen (daily checks keep the idle backlight setting; Check now / `U` stays lit): "Checking...", "Downloading N%", "Verifying...", and Cancel ("Stopping..." until cleanup finishes). `firmware/update_gate.h` provides the cross-core handshake: no flash writes begin until the loop has installed the safe display; allocation failure fails the check with the original display intact. `firmware/update_picture.h` draws two banks of centered text and a Cancel label on black. The update picture allocates nineteen separate 3.8 KB internal-DMA chunks, so it does not require one contiguous 73 KB block. Starfighter scene and packed-image decoder scratch allocate on the heap after PSRAM initialization. A `custom_dram_static_max` build guard keeps static internal RAM below 128 KB; an OTA boot checks update RAM headroom before validating itself and never marks an insufficient-memory image valid if rollback fails. `firmware/update_scanout.cpp` captures the LCD DMA channel with the scoped `--wrap=gdma_connect` linker hook, then streams circular descriptor lists reusing black rows around those strips (about 76 KB internal RAM). It masks the stock driver's VSYNC restart while active, so cache-disabled interrupts cannot interrupt the autonomous SRAM scan. Progress swaps only at a complete frame boundary, at most four times a second; normal framebuffer scan-out is restored through `esp_lcd_panel_init()` before sparse memory is freed. All switches happen on the loop core that created the driver. Cancel stops at the next network/write boundary (a blocking HTTPS request can take its timeout); an atomic handoff makes cancellation and final verification mutually exclusive; Cancel disappears when verification/boot selection begins. Daily checks start only in the dark; activity stops them at the next network/write boundary. Their SRAM screen stays dark while idle and provides stopping/checking feedback if woken until cleanup finishes. Before lighting a normal dark screen, `board::settlePanel()` waits for a DMA restart and a complete fresh scan; a timeout leaves the backlight off and retries next frame. Ordinary rendering uses 10-row internal bounce buffers and the pinned driver under `firmware/vendor/rgb` (provenance and two local patches in its README): healthy frames are never forcibly restarted, while missed EOFs and explicit recovery still restart from the top with a reset bounce index. `DisplayFrames` in `firmware/display_frames.h` gates buffer ownership: submit and the driver call are atomic with the same-core ISR; only `on_frame_buf_complete`, after the last old pixel was copied into SRAM, acknowledges reuse. VSYNC only serves clean-scan waiting on wake. A missing copy acknowledgment fails closed instead of returning a buffer that could still be read. `gfx565::expandIndexed3()` is the shared single-expansion path for shell/Pets Club and Pumpkin; the latter composes in `gfx::fb` using its own palette, without extra framebuffer allocation. A change to dimming must keep the board going fully dark when idle, or it never updates by itself; NVS namespace `"sys"` keys `ssid`, `pass`, `chan`, `last`, `home` (Radar's center: `shell::Home`'s 112 bytes raw, never resized) (plus the shell's `ran` and `lite`); the Home lookup (`startLookup`) is one more radio job: it joins the saved wifi and sends the typed address once to OpenStreetMap Nominatim (never logged or kept; only the place's coordinates and ASCII-folded name come back). `net::Radar` (`air::Feed`, set in `setup()`) is Radar's feed and the radio's longest job: while Radar is open and the screen lit, a core-0 task holds the radio (`g_busy`: the daily check, Check now and the menu's wifi jobs wait), joins once (`S_NO_WIFI` if it can't, `S_NO_SPOT` with no home, both until Radar starts it again), and every 5 s GETs adsb.fi's `/api/v3/lat/<lat>/lon/<lon>/dist/<nm>` with home rounded to 2 decimals, parsed with ArduinoJson (filtered, pools in PSRAM) into the nearest `air::MAX_PLANES` (ground ones dropped), double-buffered for `read()`; then one uncached callsign's route from adsbdb.com (32-entry cache, 404 cached as none, a route the plane is far off is dropped). It lets go on `stop()` and when the screen goes dark (so the daily update still runs overnight); on waking `read()` says `S_JOINING` and the task starts again. Every request is HTTP/1.0 (no chunked body) with a User-Agent naming porthole and the repo, and a failed request logs its URL without the query; the optional SD card (`board::mountSd()`) only supplies `/porthole/wifi.txt`. `setup()` marks a new firmware valid (`verifyRollbackLater()`, loop watchdog until then) after the first frame and before `g_shell.begin()`, so a rollback never meets a save format it can't read. `board::presentHires()` shows the back buffer: a `SURFACE_RGB565` game renders a native 480x480 frame straight into it, an indexed game's 160x160 frame is upscaled 3x into it by `board::expand()`, which rewrites only the logical rows that changed since that buffer last held an indexed frame (`gfx565::Expanded`: a hash per row and the palette; any other drawing into the buffer forgets it).

`host/` is the simulator and the tests: `sim.cpp` (the whole shell; SDL2 window, or headless `--script`/`--serve` modes; saves go to `build/host/<namespace>-<key>.sav`), `test_pet.cpp` (the Pets Club simulation self-check), `test_shell.cpp` (profiles, migration, delete, rest budget, daily cap, launcher layout), `test_biscuit.cpp` (Biscuit's rules self-check), `test_marble.cpp` (Marble Kick's physics, levels, save and drawing), `test_tilt.cpp` (`os/tilt.h`), `test_tiltfc.cpp` (Tilt FC's rules, balance, save and drawing) and `test_pumpkin.cpp` (Pumpkin's rules, a winnability bot over 100 seeds, input gates and drawing), with `grip.h` (the test grips and the inverse of `tilt::from`) shared by the tilt games' tests -- a new game's host test always lives here, as `host/test_<name>.cpp`, not inside the game's own directory. `test_display_frames`, `test_update_gate` and `test_update_picture` exercise the platform-independent update handshake and sparse picture layout in `firmware/`; no host test depends on ESP32 hardware headers.

`tools/` is dev tooling: `webemu.py` (serves `build/host/snap --serve` in a browser), `playtest.py` (the playtest runner) and `fontconv.py` (an RGB565 game's `generated/fonts.h` from lv_font_conv output, `--game biscuit|tiltfc`).

## Hard constraints

Every change must respect all seven. None of these are stylistic; each one maps to a real failure mode (a save that bricks on the next boot, a button a kid can't reach, a dog that "dies").

1. **Round screen.** The visible area is the circle of radius 80 around (80,80) in logical px (`gfx::CX`, `gfx::CY`, `gfx::R` in `os/gfx.h`; test with `gfx::inCircle(x, y[, margin])`). 1 logical px = 3 physical px = 0.33 mm (160x160 logical -> 480x480 physical). This applies at native 480x480 too: an RGB565 game's own `inCircle` is the same radius-240 circle around (240,240), just unscaled. Anything tappable must be at least 24x22 logical (8 mm) and lie entirely inside the circle: that is the exact size of the four home-screen buttons (`BTN_W=24, BTN_H=22` in `game.cpp`), not a rounded-up guideline. Text must never be cut by the bezel: before placing text at row `y`, compute the chord half-width `sqrt(80^2 - (y-80)^2)` and keep the text's full drawn width inside `[80 - halfwidth, 80 + halfwidth]`.
2. **Flat colors, and only the game's own font's glyphs.** This is per surface. An indexed (`SURFACE_INDEXED`) game: every framebuffer pixel is a palette index 0-31 (`Col` enum, `os/palette.h`) or `C_T` (255, transparent, sprites only) -- never a 33rd color or an out-of-palette blend -- and all text renders through the 8x8 font (`font8x8_basic.h`), ASCII 0-127 only: no curly quotes, no em/en dashes, no accented letters, anywhere a kid sees it. An RGB565 (`SURFACE_RGB565`) game: its art is flat fills and pre-rendered scenes, with no runtime blending beyond what its art tool already baked in -- text is the one exception, blending each glyph's 4-bit coverage against the pixel underneath at draw time -- and every drawn string is limited to its bundled font's actual glyph set -- a content gate rejects anything outside it, the same discipline as ASCII-only, just against a bigger table. Both keep the round-screen and 8 mm tap-target rules above.
3. **The buzzer is harsh.** `board::buzzer()` / `Shell::soundOn()` (the open game's `soundOn()`, gated by the profile's mute) drive a single-tone piezo. Never wire a sound to routine input (taps, navigation): only to rare, meaningful moments (growth, a trick learned, a gift, a sticker, end of a minigame), and only through the existing `Sound` enum in `game.h`. There is a per-profile mute toggle on the launcher; every sound path goes through the shell, which respects it. (Biscuit ships with no sounds at all, by design -- see its own brief.)
4. **A persisted layout is append-only.** Every game's `Save` struct and the shell's profile `Record` (`shell/profiles.h`, `porthole/p<id>`) are raw byte blobs with a magic/version/size/crc header, one per profile, written by the shell (NVS namespace per game, key `s<profile id>`). To add a field: put it immediately before `crc`, bump the version constant, and extend the loader so every older blob size/version still loads. Never reorder or resize an existing field: that corrupts every save already written to a device, silently. Each game's own `AGENTS.md` names its exact fields and the migration pattern already in use there.
5. **No game punishes absence.** Pets Club: every stat decays toward a floor and stops (`pet::FLOOR_FOOD`, `FLOOR_FUN`, `FLOOR_ENERGY`, `FLOOR_CLEAN` in `games/pets-club/pet.h`; currently 20/25/20/20), no game over, no running away, no forced reset; time away is capped at `pet::OFFLINE_CAP_SEC` (12 hours) of decay, and overnight hours count as sleep. Biscuit's contract (see its brief) is the same idea stated more broadly: no death, no guilt for absence, no expiring friendship or streaks, no lost progress. Neither game reads a weekend offline as neglect.
6. **Built for a 5-10 year old.** Short, common words in whichever glyph set the surface allows (constraint 2). Failure is gentle: a wrong answer or a miss shows the right thing and moves on; it never blocks progress or resets state. No dead ends: every screen needs an always-reachable way back (`Game::drawBackButton`/`backButton` or an equivalent visible exit); check this for any new screen.
7. **Have an independent agent play as the target child before calling it done.** Every game's gameplay/UI changes require a final-build black-box emulator playthrough by an independent `playtester`, in addition to `make check` and `make ci`. New games and major changes require a source-free first-play pass. Specify the game's target age, reading ability, experience and imprecise touch/tilt behavior. Use visible controls; explore likely attractions, wrong choices, mis-taps and recovery. Judge boredom, comprehension, meaningful choices and playability, not just completion. Iterate on mechanics, controls, player-facing instructions and the playtester's brief, then replay the affected flow after fixes until acceptance in `docs/playtesting.md` is met. Preserve the persona/brief, final build, findings/resolutions, native screenshots and input evidence. Follow that procedure and the `playtest` skill; the implementer's own run, unit tests, bots and debug tours do not replace the independent pass. An unplugged board is not an exemption. Documentation-only and non-player-visible changes need no new playthrough.

Note on constraint 1 and automated checks: `make playtest`'s UI audit fails a run on any finding. It still labels a target under 18 logical px (6 mm) FAIL and one under the real 24x22 (8 mm) box WARN, but warnings are errors: a WARN fails the run just like a FAIL. One scoped exception, a user decision of 2026-10-18: the grown-ups' system menu screens (`GROWN_UPS` in `tools/playtest.py`: `sys_info`, `sys_updates`, `sys_wifi`, `sys_pass`, `sys_join`, `sys_home`, `sys_addr`, `sys_find`, `sys_admin`, `sys_pin`, `sys_pin_set`, `sys_pin_again`, `sys_reset`, `sys_remove`, `sys_players`, `sys_player_pin`, `sys_limits`, `sys_clock`, `sys_time`, `sys_window`, `sys_allow`, `sys_zone`, `sys_zone_search`; not the kids' `sys_new` card) take 18 px targets without the 24x22 WARN, and use native-resolution anti-aliased adult typography instead of the indexed 8x8 font (a user readability decision of 2026-10-19; constraints 1 and 2). Every other rule, the 18 px FAIL included, still holds there, except on the keyboards (`KEYBOARDS`: `sys_pass`, `sys_addr`, `sys_zone_search`), whose QWERTY keys may be 12 px wide.

Note on constraint 2 and content: Pets Club's `games/pets-club/tools/check_content.py` re-renders every string through the real 8x8 font and word-wraps it into the exact box the game draws it in -- the source of truth, not a character count. Biscuit's gate is two parts: `games/biscuit/tools/check_content.py` (in `make lint`) checks the glyph set (read from `generated/fonts.h`), token validity, counts and ids; `host/test_biscuit_content.cpp` (in `make test`) measures and draws every string with `os/font.cpp` itself, tokens filled with the widest names (11 and 12 W's), in the box `games/biscuit/layout.h` gives its screen, and fails on text taller than its box or ink off the round glass; a story up to its choice, an ending or a discovery is its pages filled and joined with a space into one text (`Game::openPages`) and flowed onto screens of the 352x176 font24 page box, at most `READ_BYTES` filled and `READ_SCREENS` screens (`layout.h`), the last screen holding at least `MIN_LAST_WORDS` words at the widest names and at short ones (Sam/Pip). See the `content` skill.

## Workflows

### make targets (Makefile)

The repo root and CI call these by name; keep them working:

- `make lint`: app-specific static checks: `games/pets-club/tools/check_content.py`, `games/pets-club/tools/art.py --check`, `tools/shell_art.py --check`, `games/biscuit/tools/check_content.py`, and a `-Werror` host build of the shell, the games and the sim. (ruff and shellcheck run from the repo-root pre-commit, not here.) Biscuit's art tool's `--check` also runs here, skipped with a message where `node` is missing (CI's runner always has it).
- `make check`: `lint` + `test`. What pre-commit runs; a few seconds.
- `make ci`: `lint` + `test` + `coverage` + the sanitizer monkey playtests (`make playtest-monkey`), everything CI runs for this app except the firmware build. `coverage` plays every other scenario, so none plays twice. Every build is incremental and parallel (`NPROC=1` for serial output).
- `make coverage`: builds every `test_*` binary and `snap` with `--coverage` under `build/coverage/`, runs all the tests plus the non-monkey playtests, and writes line coverage of `os/*.cpp` and `games/*/*.cpp` to `build/coverage/coverage.xml` (Cobertura, via gcovr). Fails below `COV_MIN` in the Makefile. On macOS gcovr uses `xcrun llvm-cov gcov`; elsewhere `gcov`. Uses `gcovr` 8.3 or newer from PATH, else `uvx` fetches one.
- `make firmware` / `make flash [PORT=...]` / `make monitor [PORT=...]`: `pio run -e firmware`, upload, and the 115200-baud serial monitor. PlatformIO auto-detects the port when `PORT` is not given.

Development targets:

- `make sim`: SDL2 window. Mouse = finger. Keys: `h` +1 hour, `n` +8 hours, `d` +1 day, `r` reset save, `s` screenshot to `build/host/shot.bmp`, `p` print stats to stdout, `b` next brightness, `q`/Esc quit.
- `make snap`: headless binary, no SDL, two modes:
  - `./build/host/snap --script FILE` runs a command script (see the `tour` skill) and writes named `.bmp` files to `build/host/`.
  - `./build/host/snap --serve` speaks the stdin/stdout protocol `tools/webemu.py` drives.
  - Both accept `--now EPOCH` (fixed clock) and `--fresh` (wipe saves first); the default clock is a fixed Tuesday 16:00 local time, so unscripted snapshots are still deterministic.
- `make snap-asan`: the same headless binary built with AddressSanitizer + UBSan. Used by the chaos-monkey playtest scenarios; slower, build it only when you need sanitizer coverage.
- `make test`: builds and runs every `host/test_*.cpp` the Makefile auto-discovers, each against its own `test_<name>_SRC :=` source list: `test_pet` (`os/*.cpp`, Pets Club's `pet.cpp` and `game.cpp`), `test_shell` (`shell/profiles.cpp`, `shell/migrate.cpp`, Pets Club's `pet.cpp`), `test_biscuit` (Biscuit's rules -- header-only, no extra sources), `test_biscuit_content` (`os/*.cpp`, `games/biscuit/personalize.cpp`, `games/biscuit/art.cpp`: `personalize()`, the generated art tables, and Biscuit's pixel content gate: every string, tokens filled with the widest names, measured and drawn by `os/font.cpp` in the box `games/biscuit/layout.h` gives its screen and inside the round glass), `test_gfx565` (`os/*.cpp`: the RGB565 surface and fonts), `test_marble` (`os/*.cpp`, `games/marble-kick/*.cpp`: the tilt mapping from any grip, the ball staying on the tray, no tunneling, rails, defenders, holes, stars and moving goals, no ball-sized gaps and no resting spot a tilt cannot free, a greedy tilt at the goal failing from level 3 on, goals, the save and its v1 migration, every level's recorded solution replayed to a goal from three grips and kept in step with the playtests' `# solution` blocks (`build/host/test_marble --write-playtests`; `--levels` reports every level's design checks), and every incrementally drawn frame equal to a full repaint), `test_tilt` (`os/tilt.h`, header-only), `test_tiltfc` (`os/*.cpp`, `games/tilt-fc/*.cpp`: the dead zone from any grip, pass targeting in the cone, control switching, goals, kickoff, tackles, the whistle, the challenge -- a greedy player against one who passes and aims, and an idle one, thirty seeded matches each per level, each level no easier than the last within seed noise and the top level harder than the first --, the save, every drawn string in the font, every incrementally drawn frame equal to a full repaint, and the playtests' recorded `# match` blocks in step with the rules: `build/host/test_tiltfc --write-playtests`). Self-checks without a window: `test_marble` and `test_tiltfc` render, into memory. Must stay green. Every host build (the coverage objects too) compiles with `-ffp-contract=off`: the seeded float replays and balance numbers then come out the same under Apple clang (which fuses FMAs by default) and CI's gcc.
- `make webemu`: depends on `snap`; runs `tools/webemu.py`, serves the game at `http://127.0.0.1:8765` (`python3 tools/webemu.py 8766` for another port). The buttons under the canvas skip time and force debug states for testing.
- `make art`: runs `games/pets-club/tools/art.py`, `tools/shell_art.py`, and Biscuit's Node-based art tool (`node games/biscuit/tools/art/export-assets.mjs`, Node 22+, zero npm deps), regenerating `games/pets-club/sprites.h`, `shell/shell_sprites.h` (and, if Pillow is installed, preview sheets under `build/art/`), and `games/biscuit/generated/{scenes.h,discovery_art.h,art_data.inc,manifest.json}` from committed JS sources. All have `--check`, which `make lint` runs (Biscuit's skipped with a message if `node` is missing, an error with `REQUIRE_NODE=1`, which CI sets) -- see the `art` skill.
- `make playtest`: depends on `snap` and `snap-asan`; runs `python3 tools/playtest.py` against every scenario in `tests/playtests/*.txt`, writes `build/playtest/report.md` plus a contact-sheet PNG per scenario. See the `playtest` skill for how to read the report.
- `make clean`: removes `build/` (not `.pio/`, the firmware build cache).

### Firmware build and flash

```bash
make firmware                                  # pio run -e firmware
make flash                                     # or: make flash PORT=/dev/cu.usbmodemXXXX (Linux: usually /dev/ttyACM0)
make monitor
```

`platformio.ini` extends `[waveshare_round]` from `../../platform/waveshare-round.ini` (platform pin, board, PSRAM and USB flags) and adds only the app specifics (source dirs, partition table, upload speed, warning flags, `-Ios -Ishell -I.`). The env is `firmware`. The partition table is `partitions.csv`: nvs at 0x9000 (unchanged from PlatformIO's default, so saves survive a reflash), otadata, two 7.9 MB OTA app slots (`ota_0` at 0x10000, `ota_1` at 0x800000; `board_upload.maximum_size` = one slot, 8323072, so the build fails before firmware outgrows a slot), coredump. `make flash` also writes `boot_app0.bin`, which selects `ota_0`, so a USB flash boots what it wrote even on a board an update moved to `ota_1`.

See the `flash` skill for the PlatformIO-venv Python-dependency caveat and how to set the clock.

### Serial commands (`main.cpp` `loop()`, 115200 baud)

They work on either USB-C port: `firmware/console.h` (included by `board.h`) redefines `Serial` as a console that writes to both UART0 (the CH343 "USB to UART" port) and the ESP32-S3's own USB-Serial-JTAG port, and reads from whichever has bytes.

| Command | Effect |
| --- | --- |
| `S` | Print the active profile and the stats of every game opened since boot, the open (or last) one last (`Shell::debugPrint()`), plus free heap, current epoch, and `version= slot= update=<UpdState> pct= available= last_check=` |
| `T<epoch>` | Set the RTC and running clock to `<epoch>` (local wall-clock seconds; ignored if <= 1,600,000,000) |
| `R` | Erase every profile and every game's saves (namespaces `porthole` and each app's store), then reboot |
| `P<n>` | Clear profile `n`'s 4-digit secret code (parent escape hatch) |
| `D` | Toggle touch-position logging |
| `A` | Print the accelerometer: raw chip axes (LSB, 8192 = 1 g) and the mapped gravity `gx,gy,gz` (milli-g, screen frame, what `Input` gets) |
| `G<x>,<y>,<z>` / `G` | Hold `Input`'s gravity at that vector (milli-g, screen frame, each axis clamped to the sensor's +-4000) for testing; a bare `G` returns to the sensor (`devctl.py tilt X Y Z` / `untilt`; `devctl.py run` always ends with one) |
| `M` | Frame metrics over the last 64 frames: loop period and fps (plus the worst frame), time in shell update, render (an indexed frame's 3x expansion included) and present (the wait for the driver to take the frame), free heap, free PSRAM, largest free internal block (`devctl.py metrics`) |
| `W<ssid>\t<password>` | Save the wifi network to NVS `"sys"` (the tab is required; nothing after it = an open network) |
| `L<lat>,<lon>` | Save Radar's home (decimal degrees) to NVS `"sys"/home` without the menu's address lookup |
| `U` | Check for an update now and download it (any build; a "dev" build checks but never downloads); says "dropped" when a run or a wifi scan/test holds the radio or an update is ready |

### Hooks and CI

Hooks are managed by the repo-root pre-commit config, not by this app: it runs ruff and shellcheck repo-wide and `make -C apps/porthole check` for this app. CI runs `make ci` plus the firmware build. Run `make ci` yourself before pushing anything that touches gameplay or UI; a red CI run is a worse time to find out.

## Model policy

**opus** for anything that writes or reviews code, or judges design/polish: `game-designer`, `game-engineer`, `firmware-engineer`, `pixel-artist`, `playtester`, `reviewer`.
**sonnet** for prose and bounded research: `story-writer`.
**haiku** for mechanical sweeps (renames, formatting, single-file lookups): no standing agent above is haiku; reach for it directly, ad hoc, for that class of task.

State the model when dispatching an agent (for example: "dispatching `game-engineer` (opus) to implement this"). Between sonnet and opus for anything code-shaped, take opus.
