# Flash headroom for future games

This optimization keeps all nine games, art pixels, content and save layouts.
It is based on Toy Town implementation commit `5653dfd` (PR #91), with a separate
optimization PR so it can be reviewed independently.

| Firmware measurement | Before | After |
| --- | ---: | ---: |
| App flash used | 7,922,002 B (95.18%) | 3,950,554 B (47.47%) |
| App slot | 8,323,072 B | 8,323,072 B |
| Free app flash | 401,070 B | **4,372,518 B** |
| Static RAM | 220,176 B | 220,176 B |

Actual firmware saving: **3,971,448 bytes**, about 3.79 MiB. Free flash is now
about **4.17 MiB**, roughly eleven times the previous headroom. A future game
must still fit its own code/assets and runtime memory inside the remaining
budgets; no partition or OTA safety margin was traded away.

Machine-readable ELF reports: [before.json](before.json), [after.json](after.json).
These use the same section accounting as PlatformIO's app-size check. Named
symbol breakdowns are estimates; padding and unnamed data are not attributed.

## Changes and measured opportunities

- **Biscuit art:** replace full-frame RGB565 RLE with lossless zlib streams.
  369 unique scene frames and 96 discovery pictures shrink from 4,416,984 to
  448,492 payload bytes. Every compressed image is smaller than its RLE version.
  The 504 scene references, 96 discovery identities, dimensions and ordering
  remain fixed. Generated source is split into files below 400 KB.
- **One decoder:** move the existing Kingdom inflater into `os/packed_image.*`
  and use it for both games. It streams little-endian RGB565 rows, supports
  16/32 KiB zlib windows, clips and scales each image, and paints either display
  buffer fully. One 32 KiB dictionary plus the ROM decoder and a 960-byte row
  replaces Kingdom's existing workspace. Total static RAM is unchanged.
- **Constant sharing:** give identical header-defined story, font and palette
  tables one C++17 inline definition. The baseline contained two `BOOKS` copies,
  two 8x8 font copies, and three palette copies: 3,560 bytes of duplicated table
  data. Table contents and public layouts are unchanged. Firmware-update safety
  still uses prerendered internal-RAM DMA stripes; both font copies were already
  flash-resident before this change.
- **Future accounting:** `make -C apps/porthole flash-report` builds the firmware
  and reports exact use/free space plus largest named contributors. For JSON,
  run `python3 tools/flash_report.py --json build/flash-report.json` from the app.
  It supports default PlatformIO installations, `PLATFORMIO_CORE_DIR`, PATH and
  an explicit `--toolchain-bin`.

## Performance and verification

The [benchmark source](benchmark.cpp) draws every Biscuit scene at native 3x,
12 rounds / 6,048 frames. Compile it against baseline `5653dfd` with `-O2`, then
against this branch with `-std=c++17 -O2 -DHOST_BUILD -DPACKED`, linking `os/packed_image.cpp`
and `-lz` for the latter. Both link `os/gfx565.cpp` and Biscuit `art.cpp`, with
`-Ios -I.` from the app directory. [Three repeated samples](benchmark.json) gave
median 93.588 → 94.972 microseconds/frame (~1.5% overhead). Earlier VM samples
varied up to ~4%; these are host timings, not physical ESP32 latency claims.

- Frozen independent SHA-256 oracle proves all 600 image references match the
  original RLE pixels, even if someone changes the regenerated manifest.
- C++ tests independently freeze pixel CRCs, check every 3x output pixel and both
  alternating framebuffer targets for all pictures and scenes.
- Decoder tests cover malformed/truncated/checksum/trailing streams, too much or
  too little output, invalid metadata, clipping, extreme positions/scales, both
  window sizes, recovery and maximum dimensions. Kingdom retains its full source
  image checks and 5,000 malformed-stream fuzz cases.
- Firmware decoder object imports only the framebuffer, stack guard, memory copy/
  fill and `tinfl_decompress`: no allocation functions. Host zlib manages its own
  internal allocation; the firmware uses the fixed ROM workspace.
- Node 22.23.4 (CI major version) and Node 24.19 both reproduce generated bytes.
- `make check`, `make ci REQUIRE_NODE=1`, 74/74 playtests (zero UI findings),
  complexity and firmware build passed. Coverage: 98.7% lines (7,632 / 7,730).
- ASan/UBSan passed. LeakSanitizer cannot inspect shutdown under the cloud
  environment's ptrace restriction; only leak detection was disabled.

The palette's C++ linkage change invalidated Toy Town's source-file cache hash.
Its cache was refreshed through the pinned Pillow 12.3.0 converter; every runtime
art include remained byte-identical. No Toy Town artwork was recompressed or
reduced in resolution.

[Observed emulator evidence](blackbox/README.md) records representative live
Biscuit/Kingdom input, screenshots and before/after frame comparison. No physical
hardware testing was performed.

## What remains worth investigating

Fonts could save roughly 75 KB with bitmap compression, but the current inline
font tables already deduplicate correctly. Adding font caches/decoders would
increase complexity for a small gain beside the recovered 3.97 MB. `sscanf`
removal alone would not remove its library machinery: framework cJSON/timezone
users retain it. Builds already use `-Os`, function/data sections and linker
collection. LTO, exception changes, image downsampling and content removal were
not needed for this headroom improvement.

Toy Town's existing paletted doll/material bitstreams also have about 85 KB of
additional theoretical zlib savings (285,120 → 200,491 bytes in an offline probe).
Applying that would need indexed-image streaming or a customization cache, so it
is deferred beside the 3.97 MB already recovered. The source PNG moodboards and
TTF files are development inputs; their repository sizes do not consume device
flash unless converted runtime data references them.
